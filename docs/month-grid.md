# Month Grid & Customer Status — full rules

AGENTS.md §7 keeps the status algorithm + short rules; full hard rules below, then explanations + badge contract.

## Hard rules — full text (AGENTS.md §7 short form)

- Months **never stored**; no bill until money first reaches it.
- **Keys off MONEY, not row existence** — an empty bill (only collection voided) reads _identically_ to an untouched month.
- Partial → `"paid"`; **no `"partial"` MonthStatus**. Only presentation differs (amber **ring**, not fill; sublabel `PARTIAL`; multi-month block rings only the first cell).
- **No grace period** — current month unpaid from day one.
- **Read NOT year-scoped** — year arrows re-derive from the store, never re-query (gotcha #121). Never build a grid inside a write; never scope the fetch to a year (every pay/void gate is all-time).
- **Per-tenant unpaid rule** (`tenant_settings.UnpaidStartRule`) decides **two different things** (mixing = gotcha #83): `isNotDueYet()` (current month's colour) vs `isNotLateYet()` (when the customer reads "Overdue"). Both in `customer-payments/utils/monthDueRules.ts` — change there, never in a caller.
- **Months settle OLDEST FIRST; "earlier" = UNCOVERED, not merely overdue.** Prepaying allowed, out of order not. One pure helper `blockingUnpaidMonths()` fed by `monthStatus.uncoveredBillingMonths`. **Never feed the gate `unpaidBillingMonths`** (overdue only, gotcha #81b), and never feed `buildCustomerStatus` the uncovered list. Months in the same write never block each other.
- **Voids NEWEST FIRST**; a paid line's start date AND plan are FROZEN (`assertPaidLinesKept`). **Unskip** follows the VOID rule, not pay (gotcha #84). Skipped months never unpaid/overdue/payable.
- **Multiple plans**: 1..N service lines per customer, each its own grid + independent payments. **Service line owns the ONLY start date** — `customers` has no `start_date`.
- `monthStatus.buildCustomerStatus(...)` is the only place a list badge is decided, derived from `buildMonthGrid`. **"Paid" = owes nothing** → never with "Overdue". Absence = unknown → **no pill**, never red. One query, one arrival, no SQL mirror. `customerFlags(status)` decides pills AND the Payment status filter — never duplicate the suppression rule. Every list filter (status, payment, debts, plan, unpaid months, type, last paid, phone, portal) = ONE helper `customerFilters.ts` → `matchesCustomerFilters`, run by phone AND server; phone shows them as labelled rows in the header filters sheet (`FiltersSheet`, branch card on top), web as dropdowns in one row. Sort web-only (server-side).
- **Web's exact filters run the SAME file on the server**: `customer-status` edge function bundles `customerStatusPage.ts` (→ `monthStatus.ts`), fed compact facts by `customer_status_facts()` (SQL deciding no rule). Month rules read "today" ONLY via `currentDate()` (`core/utils/date.ts`), which `onCalendarDay` pins to the caller's day — server clock is UTC (gotcha #173). Any new clock read in a month rule must use `currentDate()`.

## Critical Business Logic: Month Grid

**`monthStatus.buildMonthGrid(customerPlan, bills, skips, year, unpaidRule)`** = **single source of truth** for month status; no other file may reimplement it. One grid per **service line** (`CustomerPlan`): `bills` = `MonthBill[]` (`charges` row + how much reached it), pre-scoped to the line; `customerPlan.startDate` = before_start boundary. Pure, no I/O. Payment slice keeps `monthGridsByLine` (keyed by line id).

**Read NOT year-scoped → years re-derive, never re-query** (all of gotcha #121). `fetchBills(customerId, lines)` stores `bills` + `skips` + `prices` (`PriceHistory`, #185) only; `buildGrids(lines, year)` = sole site of the three per-line derivations, in `CustomerPaymentPanel`'s derive effect (`year`, `bills`, `skips`), separate from its fetch effect (customer, lines, pull-to-refresh). Writes `applyCollection(collection, sign?)` / `setMonthsSkipped` only patch rows. Never a build inside a write; never a year-scoped fetch (gates `uncoveredMonthsByLine` / `paidMonthsByLine` are all-time).

```
1. month < line.startDate → "before_start" (gray, non-tappable)
2. MONEY reached month (collected > 0) → "paid" (green regular / yellow non-regular) — INCLUDING partial (balance > 0)
2b. bill WRITTEN OFF, no money → "written_off" (grey, orange text) — owes nothing, ranks above skip (#186)
3. active skip covers month → "skipped" (slate) — money wins, ranks BELOW paid
4. month in future → "future" (gray)
4b. USAGE line (facts passed): bill worked out (reading + previous reading + month price) or staff-edited bill row → "unpaid", else "waiting" (indigo) — step 5 never applies
5. CURRENT month + 'customer_start_day' + today < line's start day-of-month → "future" (gray) "not due yet"; still payable
   (PAST month always red — the billing-day wait there is the customer's "Overdue" flag, not the cell: `isNotLateYet`, #83)
6. otherwise → "unpaid" (red regular / light gray non-regular)
```

- Months never stored; generated from bills per year; no bill until money first reaches a month.
- **Keys off MONEY, never a row existing**: empty bill (only collection voided) = untouched month — `unpaid`, not debt, not covered. Row kept b/c it is the deterministic id's natural key; its price is NOT kept — re-priced at that month's price (`linePriceAt`), so a price edit reaching the month shows at next collect (gotchas #106b, #185).
- **WRITTEN-OFF month bill** (gotchas #152(e), #186): never-collected → `"written_off"` (not unpaid, not overdue, not uncovered, not owed; settled in the badge like paid); part-paid → status stays `"paid"` (rules), but every cell look (tone, badge, no amber ring, list row, portal) reads written off via `isWrittenOffMonth` (`monthGridLayout.ts`). Never-paid month written off by raising its bill already written off (`writeOffOwed` → `writeOffMonths`, deterministic id). Both cell doors (tap + 3-dot) open `BillSheet` on `hasViewableBill(entry)` = `entry.charge` **and** status `paid`/`written_off` — never `status === "paid" && entry.charge` (fell through to COLLECT). **Write off** (⋮ + selection) only on `canWriteOffMonth` (`unpaid`, not past pay limit); written-off cell offers no Void (xor constraint), no pay/skip. **Collect the rest** hidden while `writtenOffAt` set → **Undo write-off** only way forward. `MonthEntry.charge` set for any month owning a bill row, any status. `BillSheet` shows it like sale receipt (orange hero card, ✕ badge, orange amount, "Written off" pill, three write-off rows) via one `billState()` table so void / write-off / settled / partly-paid can't drift.
- **Partial = `"paid"`, only LABELLED partial.** `collected < charge.amount` (`balance > 0`) → `"paid"`; no `"partial"` `MonthStatus`; colour maps, selection guards, aggregations treat as settled. Presentation off `entry.balance > 0`: `MonthCell` = paid fill + **amber ring**, sublabel `PARTIAL` not `Paid`; `BillSheet` hero `20/50 $` (collected/owed) via `formatPaidFraction` (`core/utils/currency.ts`, shared w/ sale receipt + debt card). **Ring, not fill** (non-regular paid cell already yellow); multi-month block rings **first** cell only (`!entry.isGroupSecondary`) else seams through the joined pill. Owed amount owned by **Debts** screen; rides on `MonthEntry.balance` for drill-ins; collect sheet says _"leaves N owing"_ while typing.
- **No grace period.** Current month `"unpaid"` from day 1 → list red "Unpaid" badge (_absence_ fallback) agrees w/ grid. Tier `grace_days` removed (DB column dropped); never reintroduce "not late yet" without changing `buildMonthGrid`, badge, dashboard tile together.
- **Per-tenant unpaid rule** (`tenant_settings.UnpaidStartRule`, More → Admin → Tenant Settings, default `'month_start'`) decides **two things**; mixing = gotcha #83:
  - **CURRENT month colour**, `isNotDueYet()`: under `'customer_start_day'` not owed until the **line's own start day-of-month** (clamped to month's last day → 31st start still due in Feb). Reports `"future"`, stays payable. **Current month only**; past month red on sight.
  - **"Overdue" timing**, `isNotLateYet()`: **last month** not _late_ until this month's billing day; cell stays **red**, still blocks later payment; only badge waits. Older than last month = late on sight.
    Both in `customer-payments/utils/monthDueRules.ts` (w/ `isBeforeStartDate`), share `hasReachedStartDay` — change there, never in a caller; `Shared/src/core/utils/date.ts` = generic helpers only. Not-yet-due current month not required (owes nothing); unpaid last month owed → card red **"Unpaid"** until billing day, **"Overdue"** after.
- Multi-month payment → **coverage map**: `durationMonths > 1` covers consecutive months; months 2+ `isGroupSecondary = true`, show "Included" not "Paid". Partly-paid bundle: every covered month `"paid"`. Unpaid months of an N-month line join into one pill per start-aligned window and owe ONE bill per window (gotcha #194).
- `customer.isRegular` controls cell colors + unpaid-banner visibility.
- **Skipped months** (`skipped_months`): not expected to pay — never unpaid, never overdue, **never payable** (UI offers "Unskip"; multi-month block covering one refused, except a _locked_ skip). One row per `(customer_plan_id, billing_month)`, `skipped` toggle; unskip → `false`, row kept so it syncs. **Unskip follows VOID rule** — refused while a later month of the line is paid (`PaymentService.assertUnskippableInOrder`, `blockingPaidMonths`); that month is **payable instead** (grid swaps Unskip for pay actions; money outranks skip) → gotcha #84. Any user can skip; optional note. Every started line skipped this month → slate **"Skipped"** badge, dropped from Unpaid tab — unless older month unpaid → **"Overdue"** (skip excuses its own month, never a backlog). → `docs/features.md` → Skipped Months.
- **Settle OLDEST FIRST; "earlier" = UNCOVERED, not merely overdue** (gotcha #81b). No paying a month while an earlier month of the line is uncovered. **Prepaying allowed; out of order not.** One pure helper `blockingUnpaidMonths()` (`customer-payments/utils/payOrder.ts`) fed by `monthStatus.uncoveredBillingMonths(line, …)` (walks `buildMonthGrid` every year from line start to its **last covered month**, counts `"unpaid"` + `"future"`). **Never** feed gate `unpaidBillingMonths` (overdue only); never feed `buildCustomerStatus` the uncovered list (prepaid customers read behind). UI enforces before every collect: cell tap, quick-pay menu, grid multi-select, quick-pay deep link, list quick pay via `CustomerStatus.uncoveredLineIds` (**wider** than `overdue`). **Months in same write never block it** (Jan+Feb+Mar OK; Mar alone not). Skipped, partly-paid, before-start = not holes. Slice publishes `uncoveredMonthsByLine` beside `monthGridsByLine` (one pass, `buildGridsFor`).
- **Voids NEWEST FIRST; paid line's start date FROZEN.** Pure `blockingPaidMonths()` (mirror, `payOrder.ts`) + slice `paidMonthsByLine`, read by UI. Two voids, one gated (gotcha #109): one **hand-over** void in `BillSheet` ungated; **month BILL** void (cell "Void this month" + `BillSheet` header 3-dot, both `payments.voidMonthBill`) refused while a later month is paid, popup names month to void first (`payments.later_month_paid`); asserted in panel (popup replaces confirm) + slice (real guard); judged on every month the bill covers; partly-paid later month blocks (`buildCoverageSet`: `collected > 0`). Start-date + plan lock: `CustomerPlanService.syncLines` → `assertPaidLinesKept` (only changed dates/plans); form date input + plan dropdown disabled for any line w/ money (`useLineDrafts.isPaidLine`). Fourth door (edit payment to 0) closed by construction: amount isn't a hand-over field, undo = void. Unskip obeys void rule (#84). Paid-on-unpaid now only from legacy rows; badge says **"Overdue"**, never "✓ Paid" (= owes nothing). → gotchas #79, #81, #81b, #84.
- **Every month door decided in ONE pure file, both apps:** `customer-payments/utils/monthActions.ts` — click `monthTap`, ⋮ rows `monthMenuItems`, toolbar picks `monthSelectionGroups` / `monthSelectionItems`, `?quickPay=1` `quickPayLinkAction`, all from one `LineGates` (pay limit + all-time uncovered/paid lists). Shared `useCustomerMonthGrid` (data half `useLineGrid`) runs them + owns flows (collect, quick pay, void, write-off, history, skip) → phone `CustomerPaymentPanel` + web `MonthPanel` are views only. Phone: 4-column tiles (`cellJoins` / `cellBadge`, `monthGridLayout.ts`); web: taller tiles (same helpers) default + **months table** (status pill, bill, paid, still owed, note; list/grid icons top right). Checkbox table reports a new set → `applySelectionChange` widens each changed month to its unit (bundle moves whole). Tests `tests/suites/monthActions.test.ts`.
- **History in cell menu on every REAL month**, not only one w/ a bill (voided bill dropped from read → needed month has no `charge`; untouched reports nothing). Only `"before_start"` excluded; admin-only; position fixed by band table → `docs/ui-patterns.md`.
- **Multiple plans:** 1..N lines (`customer_plans`), own grid + payments each. **Line owns the ONLY start date** (`customers` has no `start_date`; customer starts w/ first line). Lines edited only in customer form's inline Plans editor (`customerPlans.syncLines`); panel line selector view-only. `monthStatus.buildCustomerStatus` aggregates active lines: paid only when **every** line owes nothing over **all** required months (partial = covered); overdue if any active line has earlier unpaid month. 2+ in-play plans, mixed → amber **"N/M plans paid"** (`CustomerStatus.planCount`). List "Collect all due" pays every eligible fixed-price line for current month, **skipping lines w/ older uncovered month** (collect from detail grid). → `docs/features.md` → Multiple Plans per Customer.
- **Line price = `resolveLinePrice(line)`, NEVER `plan.price`** (traps: gotcha #85). Special price `customer_plans.custom_price` + `custom_currency_id`, set inline in Plans editor by any staff. Resolver `customer-plans/utils/linePrice.ts` → `{ amount, currencyId, durationMonths, isFixed, kind }`, sole answer → form, quick pay, bulk pay, labels agree. Amount + currency (freezes `rate_per_usd_snapshot`) + `durationMonths` always travel together. Special price = **one payment** on any plan length; labels name period (`per_month` / `per_n_months`). Collect paths take resolved values from caller; `Plan` not imported by `PaymentService` or payment slice. `isFixed` → quick pay one tap vs opens collect sheet (offered either way). **Editable once billed** (unlike start date) — `buildMonthGrid` never reads price, bills snapshot `amount`. A past month's price = `linePriceAt(line, month, history)`: an edit reaches unpaid months from its picked start month on, never earlier ones (gotcha #185). Grid: `useLineGrid.priceAt(month)` feeds `monthItemFromEntry` (collect items) + web Months table figure; `linePrice` (today) stays for header, quick-pay eligibility, block span.

- **Usage (meter) lines** — one pure file `customer-payments/utils/usageBill.ts`; `monthCells` / `buildMonthGrid` / `buildCustomerStatus` / `getCustomerStatuses` / `getOverdueMonthCounts` / `unpaidBillingMonths` / `uncoveredBillingMonths` take a trailing `LineUsage` (per line) or `usageByLine` map (`usageByLineOf(lines, readings, history)`); no facts → line read by fixed rules. Bill = `usageMonthOf`: fixed fee + units × unit price, rounded 2 places; units = reading − PREVIOUS MONTH's reading (start month: `customer_plans.start_reading`), meter change = (old final − previous) + (reading − new start), typed plan = typed units; negative part → waiting `reading_below_previous` (old data only: saving is refused — `readingProblemsOf()` in `meterReadingForm.ts`, run by the form AND `UsageReadingService.save`; meter only counts up vs last AND next month, a meter change checks each meter on its own). Price = `usagePriceAt`: only rows with `fixed_fee` AND `from_month` = that month, latest wins, never carries over. `MonthCell.usage` = worked-out `UsageMonth` (bill or `waitingFor`). Waiting = not required, not unpaid, not uncovered (never blocks pay order), current month waiting = not due. Edited bill (`isEditedUsageBill`: `amount ≠ usage.computedAmount`, no money) = unpaid even without inputs; empty unedited row re-worked like #106b. Late = `isUsageNotLateYet(billedAt)` (`monthDueRules.ts`): one month after the LATER of reading `recorded_at` and the month's FIRST price save (day clamped to month end); `UnpaidStartRule` ignored. Edited bill whose month waits again (no worked-out bill) → late one month after its own month ends (`usageBilledAt`). Future or waiting usage month never payable (`isUnbilledUsage`, `monthActions.ts`). Reading fix lock = `isReadingLocked(entry, month, paidMonths)`: money on that month, or (meter) the next; `UsageReadingService.save`/`remove` re-check it from the line's bills (`errors.usage_reading_locked_paid` / `usage_units_locked_paid`). Customer grid: `payments.fetchBills` also reads the usage lines' readings (`payments.readings`), `buildGrids` passes `usageByLineOf(lines, readings, prices)` → grid + uncovered list run usage rules. Tap a `waiting` month → reading form (`monthTap` kind `reading`); ⋮ row `reading` on every usage month (Enter / Change reading|usage, greyed `why_disabled.reading_locked` / `usage_locked`). **Price of a month = `monthPriceOf(line, cell, history)`** (`useLineGrid.priceAt(entry)`, `mergeOwed`): usage line → worked-out bill only (plan price rows would read as a fixed price, `planAt`), else `linePriceAt`. Edited bill = owed by its stored row (`monthItemFromEntry`, `mergeOwed` skips its virtual month, `monthBillFigure` shows it); empty unedited usage row whose month waits again drops from owed (`waitingUsageBills`). Empty row re-priced on cash also re-writes its usage parts (`samePrice` / `repricePatch`, `chargeRevive.ts`). **Every reader passes usage facts** — one loader `usageReadingService.getUsageByLine(lines, prices?)`: list badges (phone slice, web row, server `readCustomerStatusFacts` → `facts.usageByLine`), Reports ageing, dashboard this-month bar (`countThisMonth`: this month's cell per active line; waiting = not due), owed/reminders, portal. A reader without them reads a usage line by fixed rules (waiting months turn unpaid) — never leave one out. Server bill tuple carries `computed_amount` only → `StatusCharge.usage` = `Pick<ChargeUsage, "computedAmount">` (enough for `isEditedUsageBill`). Tests `tests/suites/usageBill.test.ts`, `meterReading.test.ts`, `usageCollect.test.ts`, `usageStatus.test.ts`.

### Customer-List Status (card badges)

**`monthStatus.buildCustomerStatus(lines, payments, skips, unpaidRule)` = only place a list badge is decided**, all derived from `buildMonthGrid`. Returns `CustomerStatus`:

|Field|Meaning|
|-|-|
|`status`|settled? how far: `paid` (owes nothing, ≥1 line owed this month) · `written_off` (same, but EVERY line due this month settled by write-off, none by money; orange pill + own Payment filter, never under "Paid") · `mixed` (N/M plans) · `unpaid` (no line settled) · `skipped` (nothing expected this month b/c skip) · `not_due_yet` (no line started/reached billing day this month)|
|`overdue`|earlier month unpaid AND LATE on any active line — not last month before `customer_start_day` billing day (owed, not late, #83)|
|`planCount`|`{ paid, total }`: `paid` = lines owing **nothing** over all required months; `total` = lines that ever had a required month (**not** "due this month")|
|`notDueLineIds`|lines quick pay must not collect (covered or skipped), by THIS month|
|`uncoveredLineIds`|lines w/ earlier month **nothing collected for** → quick pay skips them. **Wider than `overdue`** on purpose; gating on `overdue` makes quick pay throw instead of skip|
|`prepaid`|soonest-ending active prepaid line's `PrepaidExpiry` (`state` `paid_until`/`expiring`/`expired`, `paidUntil`, `days`) + `everyLine` (no other kind of line); `null` = no started prepaid line|

Five rules (breaking one = how the badge broke, gotcha #56):

1. **"Paid" = owes nothing → never w/ "Overdue".** Line paid only when every required month (up to last required) paid; skipped / not-yet-due / not-started never required. `paid`, `written_off`, `skipped`, `not_due_yet` rule out `overdue` **at the source**; display suppresses nothing. Only `mixed` may pair w/ "Overdue". Card hides plain red "Unpaid" under `overdue` (redundant; oldest-first blocks current month anyway).
2. **One query, one arrival.** `getCustomerStatuses(customers, rule)` fetches active payments + skips **once** → whole `Map<customerId, CustomerStatus>`; no second scan to contradict.
3. **Absence = unknown, never unpaid.** Missing → `status={null}`, **no** pill (red-by-absence made loading / new / half-loaded read as debt).
4. **No SQL mirror.** Repos only supply rows (`findActivePayments`); aggregation never reimplemented in Postgres/SQLite.
5. **Payment status filter IS the pills.** `customerFlags(status)` (`customers/utils/customerFlags.ts`) → `CustomerFlag` list (five `status` values + `"overdue"`, minus "Unpaid" under "Overdue"); card renders it, dropdown asks whether `customerFlags(status)` holds one of `PAYMENT_FILTER_FLAGS[payment]` (`customerFilters.ts`). Options **Unpaid · Overdue · Partly paid (`mixed`) · Paid · Not due yet · Written off · Expiring soon · Expired today · Expired**, active+regular only; **Expired today** is the one option that is not a flag: `expired` pill with `days === 0` (`isExpiredToday`, card text "Expired today"), card also under Expired; two pills → under both; **Unpaid also lists every Overdue card** (its Unpaid pill is only hidden, it still owes); **Paid also lists `paid_until` + `expiring` cards** (prepaid pill holds the Paid one); `skipped` has no option. Never duplicate the suppression rule in the filter (old Unpaid tab drifted that way). **Debts → Has debts** = same contract via `hasDebtFlag(netUsd)` (same file), NOT a `CustomerFlag`: from `debts.netByCustomer`, not `buildMonthGrid` → not active+regular-limited, overlaps payment filter. **Unpaid months** (1+ / 2+ / 3+ / 6+) reads `CustomerStatus.unpaidMonths` (distinct `unpaid` months across active lines, current included), same pass; reports' aging `getOverdueMonthCounts` wraps it → can't disagree.

**Server path (web).** Exact filters over every customer → `customer-status` edge function (`docs/edge-functions.md`) runs THIS file bundled, never a copy. Rules take narrow `StatusLine` / `StatusBill` / `StatusSkip` / `StatusCustomer` (`core/types`, only fields read → compact facts, no fake rows) and read clock only via `currentDate()`, pinned to caller's day by `onCalendarDay` (server UTC — gotcha #173). Filters = `matchesCustomerFilters` (`customers/utils/customerFilters.ts`), phone list too. Rule 4 holds: `customer_status_facts()` only gathers rows. Generic `monthCells` (exported; `buildMonthGrid` = its full-row wrapper) feeds `mergeOwed.owedOf`, so the server prices unpaid months for To collect from the same cells (gotcha #193).

Slice field `customerStatuses`: refreshed by `fetchCustomerStatuses(customers)` (list mount/focus, after bulk pay/void, unpaid rule change) or patched per customer by `syncCustomerStatus` after local mutation — valid b/c `findByCustomer` not year-scoped (full history in slice).

**Prepaid lines** (`line.prepaid`; start forced to the 1st, `customer-plans/utils/prepaidLine.ts`). Started month, no money → `"no_service"` (checked after not-due-yet): owes nothing, never unpaid/overdue/uncovered/blocking, still payable; empty stored bill dropped from owed (`mergeOwed.prepaidEmptyBills`). **Paid until** = `paidUntil(paidBillingMonths(lineBills))` (`customer-payments/utils/paidUntil.ts`) = last day of newest month money reached; partial counts, voided doesn't, gaps ignored; never saved. **Expiry** = `prepaidExpiry(paidUntil, startDate)` (same file): days left count the paid-until day itself; ≤ `EXPIRING_SOON_DAYS` (3) → `expiring`; past it → `expired`, days from the day after; never paid + started → `expired`, no date; not started → none. Reads `currentDate()` (#173). Expired owes nothing, never Overdue. Customer status: `CustomerStatus.prepaid` = `customerPrepaid(lines, bills)` (`monthStatus.ts`; soonest line, `soonerExpiry`; WhatsApp renewal reminder reads the same fn — `docs/whatsapp.md`) → `customerFlags` adds one pill (`paid_until` green / `expiring` amber / `expired` gray, text `prepaidPillLabel`); all-prepaid customer drops its `paid`/`not_due_yet`/`skipped` pill (the expiry says it). Words = `customer-payments/utils/prepaidText.ts` (`prepaidTextParts` → `payments.*`, portal `portal.*`): grid header (`useLineGrid.paidUntilLabel`, phone + web) + portal `ServiceLines` (`PortalModel.expiryByLine`) show "Paid until <date> · Expires in X days / Expired X days ago"; none yet → "No payment yet". Tests `tests/suites/prepaidExpiry.test.ts`.
**Pay until** (prepaid + fixed-price line; grid header button, phone `ActionMenu` / web `PayUntilDialog`): pure `payUntilChoices()` (`customer-payments/utils/payUntil.ts`, fed by `useLineGrid.payUntilChoices`, builds cells via `buildMonthGrid` for every year it needs). Start = `payUntilStart`: later of month after newest paid, this month, line start (block-aligned for N-month plans) → expired customer pays whole months from now, missed months stay `no_service`. One choice per payable block, `PAY_UNTIL_MONTHS` (12) ahead; skipped months left out, stops at `payLimit`; part-paid newest month rides along (its rest). Pick → `payOrderBlocker` → `openCollectFor(months)` = the normal collect form, ONE collection, each month its own bill at `priceAt`; nothing saved by the picker. Option = month, per-currency total of the items, new "Paid until". Void = the hand-over void (all its months, #109). **One payment = one pill**: `MonthBill.collectionIds` (only `findMonthChargesForCustomer` fills it: web extra `collection_items` read, offline `GROUP_CONCAT`; `mergeCollection` adds/drops the hand-over) → `paymentLinks(bills)` (bill settled WHOLE by its only hand-over, which paid 2+ bills) → `cellJoins(…, links)` groups those months like a bundle; partial or multi-payer bill stands alone. Tests `tests/suites/payUntil.test.ts`.
