# Month Grid & Customer Status — full rules

CLAUDE.md keeps status algorithm + hard rules; explanations + badge contract here.

## Critical Business Logic: Month Grid

**`monthStatus.buildMonthGrid(customerPlan, bills, skips, year, unpaidRule)`** = **single source of truth** for month status; no other file may reimplement it. One grid per **service line** (`CustomerPlan`): `bills` = `MonthBill[]` (`charges` row + how much reached it), pre-scoped to the line; `customerPlan.startDate` = before_start boundary. Pure, no I/O. Payment slice keeps `monthGridsByLine` (keyed by line id).

**Read NOT year-scoped → years re-derive, never re-query** (all of gotcha #121). `fetchBills(customerId, lines)` stores `bills` + `skips` + `prices` (`PriceHistory`, #185) only; `buildGrids(lines, year)` = sole site of the three per-line derivations, in `CustomerPaymentPanel`'s derive effect (`year`, `bills`, `skips`), separate from its fetch effect (customer, lines, pull-to-refresh). Writes `applyCollection(collection, sign?)` / `setMonthsSkipped` only patch rows. Never a build inside a write; never a year-scoped fetch (gates `uncoveredMonthsByLine` / `paidMonthsByLine` are all-time).

```
1. month < line.startDate → "before_start" (gray, non-tappable)
2. MONEY reached month (collected > 0) → "paid" (green regular / yellow non-regular) — INCLUDING partial (balance > 0)
2b. bill WRITTEN OFF, no money → "written_off" (grey, orange text) — owes nothing, ranks above skip (#186)
3. active skip covers month → "skipped" (slate) — money wins, ranks BELOW paid
4. month in future → "future" (gray)
5. CURRENT month + 'customer_start_day' + today < line's start day-of-month → "future" (gray) "not due yet"; still payable
   (PAST month always red — the billing-day wait there is the customer's "Overdue" flag, not the cell: `isNotLateYet`, #83)
6. otherwise → "unpaid" (red regular / light gray non-regular)
```

- Months never stored; generated from bills per year; no bill until money first reaches a month.
- **Keys off MONEY, never a row existing**: empty bill (only collection voided) = untouched month — `unpaid`, not debt, not covered. Row kept b/c it is the deterministic id's natural key; its price is NOT kept — re-priced at that month's price (`linePriceAt`), so a price edit reaching the month shows at next collect (gotchas #106b, #185).
- **WRITTEN-OFF month bill** (gotchas #152(e), #186): never-collected → `"written_off"` (not unpaid, not overdue, not uncovered, not owed; settled in the badge like paid); part-paid → `"paid"` + amber ring. Never-paid month written off by raising its bill already written off (`writeOffOwed` → `writeOffMonths`, deterministic id). Both cell doors (tap + 3-dot) open `BillSheet` on `hasViewableBill(entry)` = `entry.charge` **and** status `paid`/`written_off` — never `status === "paid" && entry.charge` (fell through to COLLECT). **Write off** (⋮ + selection) only on `canWriteOffMonth` (`unpaid`, not past pay limit); written-off cell offers no Void (xor constraint), no pay/skip. **Collect the rest** hidden while `writtenOffAt` set → **Undo write-off** only way forward. `MonthEntry.charge` set for any month owning a bill row, any status. `BillSheet` shows it like sale receipt (orange hero card, ✕ badge, orange amount, "Written off" pill, three write-off rows) via one `billState()` table so void / write-off / settled / partly-paid can't drift.
- **Partial = `"paid"`, only LABELLED partial.** `collected < charge.amount` (`balance > 0`) → `"paid"`; no `"partial"` `MonthStatus`; colour maps, selection guards, aggregations treat as settled. Presentation off `entry.balance > 0`: `MonthCell` = paid fill + **amber ring**, sublabel `PARTIAL` not `Paid`; `BillSheet` hero `20/50 $` (collected/owed) via `formatPaidFraction` (`core/utils/currency.ts`, shared w/ sale receipt + debt card). **Ring, not fill** (non-regular paid cell already yellow); multi-month block rings **first** cell only (`!entry.isGroupSecondary`) else seams through the joined pill. Owed amount owned by **Debts** screen; rides on `MonthEntry.balance` for drill-ins; collect sheet says _"leaves N owing"_ while typing.
- **No grace period.** Current month `"unpaid"` from day 1 → list red "Unpaid" badge (_absence_ fallback) agrees w/ grid. Tier `grace_days` removed (DB column dropped); never reintroduce "not late yet" without changing `buildMonthGrid`, badge, dashboard tile together.
- **Per-tenant unpaid rule** (`tenant_settings.UnpaidStartRule`, Admin → Tenant Settings, default `'month_start'`) decides **two things**; mixing = gotcha #83:
  - **CURRENT month colour**, `isNotDueYet()`: under `'customer_start_day'` not owed until the **line's own start day-of-month** (clamped to month's last day → 31st start still due in Feb). Reports `"future"`, stays payable. **Current month only**; past month red on sight.
  - **"Overdue" timing**, `isNotLateYet()`: **last month** not _late_ until this month's billing day; cell stays **red**, still blocks later payment; only badge waits. Older than last month = late on sight.
    Both in `customer-payments/utils/monthDueRules.ts` (w/ `isBeforeStartDate`), share `hasReachedStartDay` — change there, never in a caller; `Shared/src/core/utils/date.ts` = generic helpers only. Not-yet-due current month not required (owes nothing); unpaid last month owed → card red **"Unpaid"** until billing day, **"Overdue"** after.
- Multi-month payment → **coverage map**: `durationMonths > 1` covers consecutive months; months 2+ `isGroupSecondary = true`, show "Included" not "Paid". Partly-paid bundle: every covered month `"paid"`.
- `customer.isRegular` controls cell colors + unpaid-banner visibility.
- **Skipped months** (`skipped_months`): not expected to pay — never unpaid, never overdue, **never payable** (UI offers "Unskip"; multi-month block covering one refused, except a _locked_ skip). One row per `(customer_plan_id, billing_month)`, `skipped` toggle; unskip → `false`, row kept so it syncs. **Unskip follows VOID rule** — refused while a later month of the line is paid (`PaymentService.assertUnskippableInOrder`, `blockingPaidMonths`); that month is **payable instead** (grid swaps Unskip for pay actions; money outranks skip) → gotcha #84. Any user can skip; optional note. Every started line skipped this month → slate **"Skipped"** badge, dropped from Unpaid tab — unless older month unpaid → **"Overdue"** (skip excuses its own month, never a backlog). → `docs/features.md` → Skipped Months.
- **Settle OLDEST FIRST; "earlier" = UNCOVERED, not merely overdue** (gotcha #81b). No paying a month while an earlier month of the line is uncovered. **Prepaying allowed; out of order not.** One pure helper `blockingUnpaidMonths()` (`customer-payments/utils/payOrder.ts`) fed by `monthStatus.uncoveredBillingMonths(line, …)` (walks `buildMonthGrid` every year from line start to its **last covered month**, counts `"unpaid"` + `"future"`). **Never** feed gate `unpaidBillingMonths` (overdue only); never feed `buildCustomerStatus` the uncovered list (prepaid customers read behind). UI enforces before every collect: cell tap, quick-pay menu, grid multi-select, quick-pay deep link, list quick pay via `CustomerStatus.uncoveredLineIds` (**wider** than `overdue`). **Months in same write never block it** (Jan+Feb+Mar OK; Mar alone not). Skipped, partly-paid, before-start = not holes. Slice publishes `uncoveredMonthsByLine` beside `monthGridsByLine` (one pass, `buildGridsFor`).
- **Voids NEWEST FIRST; paid line's start date FROZEN.** Pure `blockingPaidMonths()` (mirror, `payOrder.ts`) + slice `paidMonthsByLine`, read by UI. Two voids, one gated (gotcha #109): one **hand-over** void in `BillSheet` ungated; **month BILL** void (cell "Void this month" + `BillSheet` header 3-dot, both `payments.voidMonthBill`) refused while a later month is paid, popup names month to void first (`payments.later_month_paid`); asserted in panel (popup replaces confirm) + slice (real guard); judged on every month the bill covers; partly-paid later month blocks (`buildCoverageSet`: `collected > 0`). Start-date lock: `CustomerPlanService.syncLines` → `assertStartDatesUnlocked` (only changed dates); form date input disabled for any line w/ money. Fourth door (edit payment to 0) closed by construction: amount isn't a hand-over field, undo = void. Unskip obeys void rule (#84). Paid-on-unpaid now only from legacy rows; badge says **"Overdue"**, never "✓ Paid" (= owes nothing). → gotchas #79, #81, #81b, #84.
- **Every month door decided in ONE pure file, both apps:** `customer-payments/utils/monthActions.ts` — click `monthTap`, ⋮ rows `monthMenuItems`, toolbar picks `monthSelectionGroups` / `monthSelectionItems`, `?quickPay=1` `quickPayLinkAction`, all from one `LineGates` (pay limit + all-time uncovered/paid lists). Shared `useCustomerMonthGrid` (data half `useLineGrid`) runs them + owns flows (collect, quick pay, void, write-off, history, skip) → phone `CustomerPaymentPanel` + web `MonthPanel` are views only. Phone: 4-column tiles (`cellJoins` / `cellBadge`, `monthGridLayout.ts`); web: taller tiles (same helpers) default + **months table** (status pill, bill, paid, still owed, note; list/grid icons top right). Checkbox table reports a new set → `applySelectionChange` widens each changed month to its unit (bundle moves whole). Tests `tests/suites/monthActions.test.ts`.
- **History in cell menu on every REAL month**, not only one w/ a bill (voided bill dropped from read → needed month has no `charge`; untouched reports nothing). Only `"before_start"` excluded; admin-only; position fixed by band table → `docs/ui-patterns.md`.
- **Multiple plans:** 1..N lines (`customer_plans`), own grid + payments each. **Line owns the ONLY start date** (`customers` has no `start_date`; customer starts w/ first line). Lines edited only in customer form's inline Plans editor (`customerPlans.syncLines`); panel line selector view-only. `monthStatus.buildCustomerStatus` aggregates active lines: paid only when **every** line owes nothing over **all** required months (partial = covered); overdue if any active line has earlier unpaid month. 2+ in-play plans, mixed → amber **"N/M plans paid"** (`CustomerStatus.planCount`). List "Collect all due" pays every eligible fixed-price line for current month, **skipping lines w/ older uncovered month** (collect from detail grid). → `docs/features.md` → Multiple Plans per Customer.
- **Line price = `resolveLinePrice(line)`, NEVER `plan.price`** (traps: gotcha #85). Special price `customer_plans.custom_price` + `custom_currency_id`, set inline in Plans editor by any staff. Resolver `customer-plans/utils/linePrice.ts` → `{ amount, currencyId, durationMonths, isFixed, kind }`, sole answer → form, quick pay, bulk pay, labels agree. Amount + currency (freezes `rate_per_usd_snapshot`) + `durationMonths` always travel together. Special price = **one payment** on any plan length; labels name period (`per_month` / `per_n_months`). Collect paths take resolved values from caller; `Plan` not imported by `PaymentService` or payment slice. `isFixed` → quick pay one tap vs opens collect sheet (offered either way). **Editable once billed** (unlike start date) — `buildMonthGrid` never reads price, bills snapshot `amount`. A past month's price = `linePriceAt(line, month, history)`: an edit reaches unpaid months from its picked start month on, never earlier ones (gotcha #185). Grid: `useLineGrid.priceAt(month)` feeds `monthItemFromEntry` (collect items) + web Months table figure; `linePrice` (today) stays for header, quick-pay eligibility, block span.

> Multi-month bills, payment scenarios (A/B/C/D, full vs partial), snapshot/currency rules → `docs/features.md`, `docs/gotchas.md`.

### Customer-List Status (card badges)

**`monthStatus.buildCustomerStatus(lines, payments, skips, unpaidRule)` = only place a list badge is decided**, all derived from `buildMonthGrid`. Returns `CustomerStatus`:

|Field|Meaning|
|-|-|
|`status`|settled? how far: `paid` · `mixed` (N/M plans) · `unpaid` · `skipped` · `not_due_yet`|
|`overdue`|earlier month unpaid AND LATE on any active line — not last month before `customer_start_day` billing day (owed, not late, #83)|
|`planCount`|`{ paid, total }`: `paid` = lines owing **nothing** over all required months; `total` = lines that ever had a required month (**not** "due this month")|
|`notDueLineIds`|lines quick pay must not collect (covered or skipped), by THIS month|
|`uncoveredLineIds`|lines w/ earlier month **nothing collected for** → quick pay skips them. **Wider than `overdue`** on purpose; gating on `overdue` makes quick pay throw instead of skip|

Five rules (breaking one = how the badge broke, gotcha #56):

1. **"Paid" = owes nothing → never w/ "Overdue".** Line paid only when every required month (up to last required) paid; skipped / not-yet-due / not-started never required. `paid`, `skipped`, `not_due_yet` rule out `overdue` **at the source**; display suppresses nothing. Only `mixed` may pair w/ "Overdue". Card hides plain red "Unpaid" under `overdue` (redundant; oldest-first blocks current month anyway).
2. **One query, one arrival.** `getCustomerStatuses(customers, rule)` fetches active payments + skips **once** → whole `Map<customerId, CustomerStatus>`; no second scan to contradict.
3. **Absence = unknown, never unpaid.** Missing → `status={null}`, **no** pill (red-by-absence made loading / new / half-loaded read as debt).
4. **No SQL mirror.** Repos only supply rows (`findActivePayments`); aggregation never reimplemented in Postgres/SQLite.
5. **Payment status filter IS the pills.** `customerFlags(status)` (`customers/utils/customerFlags.ts`) → `CustomerFlag` list (five `status` values + `"overdue"`, minus "Unpaid" under "Overdue"); card renders it, dropdown asks `customerFlags(status).includes(payment)`. Options **Unpaid · Overdue · Partly paid (`mixed`) · Paid · Not due yet**, active+regular only; two pills → under both; `skipped` has no option. Never duplicate the suppression rule in the filter (old Unpaid tab drifted that way). **Debts → Has debts** = same contract via `hasDebtFlag(netUsd)` (same file), NOT a `CustomerFlag`: from `debts.netByCustomer`, not `buildMonthGrid` → not active+regular-limited, overlaps payment filter. **Unpaid months** (1+ / 2+ / 3+ / 6+) reads `CustomerStatus.unpaidMonths` (distinct `unpaid` months across active lines, current included), same pass; reports' aging `getOverdueMonthCounts` wraps it → can't disagree.

**Server path (web).** Exact filters over every customer → `customer-status` edge function (`docs/edge-functions.md`) runs THIS file bundled, never a copy. Rules take narrow `StatusLine` / `StatusBill` / `StatusSkip` / `StatusCustomer` (`core/types`, only fields read → compact facts, no fake rows) and read clock only via `currentDate()`, pinned to caller's day by `onCalendarDay` (server UTC — gotcha #173). Filters = `matchesCustomerFilters` (`customers/utils/customerFilters.ts`), phone list too. Rule 4 holds: `customer_status_facts()` only gathers rows.

Slice field `customerStatuses`: refreshed by `fetchCustomerStatuses(customers)` (list mount/focus, after bulk pay/void, unpaid rule change) or patched per customer by `syncCustomerStatus` after local mutation — valid b/c `findByCustomer` not year-scoped (full history in slice).
