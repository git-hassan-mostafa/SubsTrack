1. **Payments use upsert** — `UNIQUE(customer_plan_id, billing_month)` (per service line, not customer) → re-paying voided month upserts existing row (nulls `voided_at`), no insert. Several lines → one payment per line per month; `onConflict` `customer_plan_id,billing_month`.
2. **Payment amount is a snapshot** — stored at record time, never recomputed from `plan.price`; historical amounts survive plan changes/deletes.
3. **`superadmin` role in DB, hidden in SubsTrack** — in `UserRole` type, filtered from user-management UI; only SuperAdmin app uses it.
4. **Login email is synthetic** — `username@tenantcode.com` = unique-id convention in Supabase Auth, not a real email.
5. **Language change reloads app** — Arabic RTL via `I18nManager` needs reload; handled in `storage.ts`.
6. **In-flight double-tap guard** — stores check `if (get().loadingCreate) return` first → no duplicate payment submits.
7. **Year-scoped payment loading** — `paymentStore` fetches only displayed year; changing year fetches (cached by year).
8. **`before_start` = 4th month status** — months before `line.startDate` (the `customer_plans` row's own start; `customers` has no `start_date`) → non-tappable, gray regardless of other logic.
9. **No cross-slice imports at module scope** — slices import peer types only, never slice creator/per-slice hook; cross-slice reads inside actions via `get().<otherSlice>`. Caller data (tier, usage, currency) = params from component.
10. **SuperAdmin uses service role key** — `supabaseAdmin.ts` bypasses RLS (full DB access).
11. **Cairo font for Arabic** — loaded via `expo-font` at root layout; `useAppFont` applies it; custom `Text` component picks font family per current language.
12. **`billing_month` always YYYY-MM-01** — validated in PaymentService before insert.
13. **Multi-month payments store bundle price, not per-month** — `payment.amount` = total bundle; `durationMonths` tells grid how many consecutive months covered from `billingMonth`.
14. **`isGroupSecondary` in MonthEntry** — months 2+ of a multi-month block have `isGroupSecondary = true`; grid uses it for visual merge (no gap, "Included" sublabel) and to block tapping them.
15. **Multi-month conflict resolution** — `createMultiMonthPayment` shifts `effectiveStart` + shrinks `effectiveDuration` when leading months already paid: starts at first uncovered month, covers only remaining months of original block.
16. **Non-regular customers never in unpaid counts** — dashboard `unpaidThisMonth` + "Unpaid" tab query only `is_regular = true` active customers; non-regular still pay normally. Multi-plan: aggregated over active service lines — `unpaidThisMonth` counts customer once if any active line uncovered this month (`CustomerRepository.countUnpaidForMonth` joins `customer_plans`); list badge (`monthStatus.buildCustomerStatus`) needs every DUE active line covered for green (partial = covered, #34). Honours tenant `UnpaidStartRule` (via `isNotDueYet`): line whose billing day hasn't come isn't unpaid; tile, grid, "Not due yet" badge agree. Rule threaded as param (dashboard slice → `DashboardService.getMetrics` → repository), never read inside repository — see #87.
17. **EmptyState first-data button** — `EmptyState` optional `onAction` + `actionLabel`; lists pass them → "Create First X" button when empty and not searching.
18. **`null currency_id` = USD** — every money column (`plans.price`, `payments.amount_due`/`amount_paid`, `users.display_currency_id`) treats `null` as USD; USD never inserted as `currencies` row.
19. **CurrencyInput does NOT convert on currency change** — USD → LBP keeps typed `100` as `100 LBP`; user means "this number in other unit".
20. **Display currency = TENANT setting, not device pref** — `tenant_settings` key `DisplayCurrencyId`, read only via `useDisplayCurrencyId()` (`Shared/src/state/hooks/useTenantSettingSlice.ts`). Never in `uiPrefStore` (AsyncStorage): it used to live there, so staff of one org saw different currencies and reinstall lost the choice. No `display_currency_id` column on `users`/`tenants` — don't add. **Admin-writable only** (RLS on `tenant_settings`), resets on logout w/ slice, re-fetched by `primePostAuth`; unknown/soft-deleted id → USD via `findCurrency`.
21. **`rate_per_usd_snapshot` freezes payment USD value** — every payment row carries live `currencies.rate_per_usd` at record time. PaymentDetailSheet (receipt), CustomerPaymentPanel year total, Dashboard aggregates use frozen rate → live-rate edits never shift history. USD (`currencyId === null`) snapshot = 1. Plan prices use live rate. Captured at boundary: `PaymentFormSheet` resolves `Currency` from `useCurrencyStore` → `paymentStore.createPayment`/`createMultiMonthPayment` extract `currency?.ratePerUsd ?? 1` → `PaymentService`. **Editing** re-snapshots: `PaymentService.updatePayment(id, amountDue, amountPaid, currency)` recomputes `ratePerUsdSnapshot` from the (maybe new) currency. Display via `paymentSnapshotCurrency(payment, currencies)` (`Shared/src/core/utils/currency.ts`): live `Currency` cloned w/ `ratePerUsd` = snapshot.
22. **Dashboard aggregates in USD via snapshots** — `DashboardService.getMetrics()` fetches month's `{amount, rate_per_usd_snapshot}` rows, divides each by snapshot, sums; screen re-formats USD total into tenant display currency.
23. **`authStore.restoreSession`/`login` prime currency store** — after auth, `useCurrencyStore.fetchCurrencies()`; `logout` resets it.
24. **`currencies.code` uppercase A-Z, 2-8 chars, never 'USD'** — CHECK constraint + `CurrencyService.validate()`.
25. **Quick Pay `?quickPay=1` handshake** — customer list opens customer page w/ `?quickPay=1` when quick pay finds 2+ lines w/ no set price (each needs own typed amount). Shared `useCustomerMonthGrid` takes `quickPayLink { requested, consume, schedule? }`: once bills read, opens collect form for this month of selected line, unless `quickPayLinkAction` says month skipped or older month uncovered ( → popup). Ref fires once; `consume()` removes param (phone `router.setParams`, web `setSearchParams(…, { replace: true })`) → reload never re-collects. Phone passes `schedule` (InteractionManager) so sheet waits for screen push; cancel scheduled open only on unmount — **never in effect's own cleanup** (param removal re-renders → cancels it).
26. **`branch_id NULL` semantics** — `users`: NULL = tenant-wide admin (picker `nullable` only when `role === 'admin'`). `plans`/`products`: NULL = SHARED item visible to every branch; tenant-wide admins pick freely (`PlanFormSheet`/`ProductFormSheet` `nullable={user?.branchId === null}`; neither `PlanService` nor `ProductService` requires a branch). `customers`: NULL = **legacy-only** UNASSIGNED — picker `nullable={false}`, `CustomerService` rejects `branch_id = null` when tenant has any active branch; arises only when branch deleted (FK `ON DELETE SET NULL`). `BranchSelector` "Unassigned" filter surfaces orphans.
27. **Tenant-wide admin = `users.branch_id IS NULL`** — no separate role; any admin w/o branch = tenant "super admin"; multiple allowed. Unrelated to SaaS `superadmin` role (SuperAdmin app).
28. **Branch filter = pure UI state** — `uiPrefStore.currentBranchId` (persisted to AsyncStorage). RLS lets tenant-wide admins see all; app passes `?branch=X` per query to narrow. Branch-scoped users ignore `currentBranchId`, see only their branch (`users.branch_id`, RLS-enforced).
29. **`BranchSelector` = compact chip inside `PageHeader`** — small pill (`rounded-full px-3 py-1`; gray when "All Branches" active, indigo-tinted when filtered) directly under page subtitle. `PageHeader` always renders `<BranchSelector />`. Dashboard (no `PageHeader`): chip in greeting block of `SubsTrack/src/modules/dashboard/screens/DashboardScreen.tsx`. Tap opens shared `DropdownModal` exported from `SubsTrack/src/shared/components/Dropdown.tsx` (same search/option-list UX as form-field dropdowns). Returns `null` for branch-scoped users and tenants w/ <2 active branches; same gate = `useIsMultiBranchActive()` in `SubsTrack/src/shared/components/BranchPicker.tsx`, shared w/ `BranchPicker` so every dropdown/picker/filter hides in lockstep.
30. **New tenants auto-get "Default Branch"** — `TenantService.createTenant` (`SuperAdmin/src/modules/tenants/services/TenantService.ts`) inserts `Default Branch` right after tenant row, before admin auth user. `branches.tenant_id` `ON DELETE CASCADE` → rollbacks clean up.
31. **Single-branch tenants act as if branches don't exist** — 1 active branch → `BranchSelector` + every `BranchPicker` hide. Form sheets auto-bind new records to lone branch (`CustomerFormSheet`, `PlanFormSheet`, `UserFormSheet` for `role='user'`); `UserFormSheet` resets `branchId` to `null` when role flips to `admin`. Auto-fill on create only, never edit. Branches CRUD stays reachable → 2nd branch → multi-branch UI.
32. **Branch mandatory for customers + staff users once any branch exists** — `BranchPicker` `nullable={false}` in `CustomerFormSheet` and (when `role === 'user'`) `UserFormSheet`; submit disabled until picked; services re-validate (`CustomerService.validateInput`, `UserService.validateBranchAssignment`) via `tenantHasBranches` flag from `useBranchStore`. Plans + products NOT mandatory → #26. Tenant-wide admins (`users.role === 'admin'`, `branch_id = null`) exempt for customers/users. 0-branch (legacy) tenants skip enforcement.
33. **Self-service signup goes through Edge Function, never direct inserts** — app ships only anon key; no INSERT policy on `tenants`/`branches`/`tier_plans`. Public `create-tenant` fn (`SubsTrack/supabase/functions/create-tenant/index.ts`, `--no-verify-jwt`) = **sole** anon path to create tenant. Service-role key, cascading rollback: lookup Free tier id → `tenants(tier_id=Free)` → `branches` ('Default Branch') → `auth.users` → `public.users` (role=`superadmin`, branch_id=null). Pre-check on organization screen: `is_tenant_code_available` (SECURITY DEFINER RPC granted to `anon`, boolean yes/no oracle, no row data). Owner has `superadmin` role (as SuperAdmin's `TenantService.createTenant`) → filtered from own Users screen (#3), same as tenants created from SuperAdmin today. Paid-plan gating goes here (`paymentToken` accepted-but-ignored) + `subscriptionStore.upgrade()`.
34. **Partial payment reports `"paid"` — NO `"partial"` `MonthStatus`** — payment w/ `amount_paid > 0` covering month (even `balance > 0`) → `monthStatus.buildMonthGrid` emits `status: "paid"`; `MonthStatus` = `"paid" | "unpaid" | "future" | "before_start"`; partial has no distinct cell color/label. Outstanding `balance` shown **only** in Debts tab ("months" category) + drill-ins; rides on `MonthEntry.balance`; drill-ins read `payment.balance`: `PaymentDetailSheet` (amber card + "{amount} added to debts"), `PaymentListCard` Payments-tab ledger (partial badge; transaction-level `PaymentStatusFilter = "all" | "paid" | "partial"`, `balance > 0`). `PaymentAmountPaidSection` (shared w/ `SaleFormSheet`): amber `payments.partial_debt_notice` when paid < due. List badges: `CustomerStatus.status` (#56) = `"paid"` when every DUE line covered (partial counts) → single-plan partial reads green; `"mixed"` = multi-plan, some covered + ≥1 not → amber "N/M plans paid". `buildCustomerStatus` (only implementation) treats **any covering payment as settled** regardless of balance; `createPayment`/`createMultiMonthPayment`/`updatePayment`/`voidPayment` re-run it via `syncCustomerStatus`. Unpaid tab + Quick Pay gating treat `"paid"`/`"mixed"` as "has payment record this month". Partial = full wherever a record matters (`PaymentDetailSheet`, `MonthGrid` grouping, `PaymentFormSheet` conflicts, `CustomerPaymentPanel` `paidCount`). Overdue = own pill: `CustomerStatus.overdue` = any active line has unpaid month before this one; shown beside month pill (#56) → "✓ Paid + Overdue" is real; same `buildCustomerStatus` pass as `status`, from grids built per line across every year from `startDate` to now → decision stays inside `buildMonthGrid` (rule #1). `CustomerListScreen` refreshes map via `useFocusEffect` (keyed `customers`). Unpaid tab: `status.overdue || status.status === "unpaid" || status.status === "mixed"`. **No grace period (removed on purpose):** red `"unpaid"` badge = absence fallback, agrees w/ grid only b/c grid turns month `"unpaid"` on its first day. `tier_plans.grace_days` + `graceDays` params deleted; a future "not late yet" state must change `buildMonthGrid`, card badge, Unpaid tab and dashboard `unpaidThisMonth` tile together (else collected-% ring reads 100%).
35. **Sales independent from subscription payments** — `sales`/`payments` = separate tables, services, slices, screens; share only snapshot rate (`rate_per_usd_snapshot`). Don't unify — subscriptions are month-shaped (`billing_month`, `duration_months`), sales aren't. Only intersection: `DashboardService.getMetrics()` sums both in USD by each row's frozen rate → `subscriptionRevenue` + `salesRevenue` + combined `monthlyRevenue`.
    - **Sale = HEADER (`sales`) + ≥1 LINES (`sale_items`)** (like `customers` → `customer_plans`). Header owns **single currency + `rate_per_usd_snapshot`**, **`total_amount`** (**app-written, NOT generated** — can't sum child table), `amount_paid` (partial → one "Sales" debt), **frozen `items_summary`**; debt/wallet/dashboard stay header-level. `sale_items` carry `product_id`/`product_name_snapshot`/`quantity`/`unit_amount`; `line_total` derived in mapper (no column). **One currency per sale** — form converts each product's catalog price via `convert()`; lines carry no currency. Product soft-vs-hard delete counts **`sale_items.product_id`** refs, not `sales`.
    - **`items_summary` = search field + list/debt/wallet label** — frozen summary built by `SaleService` at create. `SaleCard` title, `SaleDetailSheet` hero, Debts "sales" `label`, `WalletItem.label` read `sale.itemsSummary` (not `productNameSnapshot`; e.g. `"Water ×2, Bread"`). Lean reads (`partialSales`, `heldForWallet`, dashboard totals) need **no `sale_items` join**; only list/detail do `sale_items(*, products(*))`. Sales-tab **product filter** resolves via `sale_items` (web: sale-ids sub-query → `.in('id', …)`; offline: `EXISTS`) b/c `product_id` not on header.
36. **`paymentSnapshotCurrency()` works on any row w/ `currencyId` + `ratePerUsdSnapshot`** — `Shared/src/core/utils/currency.ts` helper is shape-based. Reuse for sales (`SaleCard`, `SaleDetailSheet`) → historical USD drift-free when tenant edits live `currencies.rate_per_usd`. New snapshot entity → reuse, don't copy.
37. **`AsyncEntityPicker` replaces `Dropdown` only when option list too large for memory** — `Dropdown` filters client-side over preloaded array (branches, currencies, plans). `AsyncEntityPicker`: `loadPage(search, page)`, `useDebounce` 300 ms, `FlatList.onEndReached` paging, stale responses dropped via `requestToken` ref (like `customerSlice.searchToken`). Use for customers (`SaleFormSheet`) + large pickers; don't migrate small static dropdowns.
38. **`app_options` = global config + seeds default LBP currency** — app-wide key/value table (no `tenant_id`); SaaS owner manages in SuperAdmin **Options** tab (full CRUD, service-role); read-only in SubsTrack (`options` module + `optionSlice`, fetched at bootstrap **and** re-primed in `primePostAuth`, **not** reset on `logout`; RLS `anon` + `authenticated` `SELECT`: flags gate pre-auth UI). `LiraRate` = default USD → LBP rate. Flags: `AllowPlanUpgrade` (upgrade button → WhatsApp "contact to upgrade" link to `SupportWhatsAppNumber`), `AllowSelfServiceSignup` (hides login "Create organization" **and** enforced in `create-tenant`). Read via hooks in `useOptionSlice.ts` (`useCanUpgradePlan`/`useSelfServiceSignupEnabled`/`useSupportWhatsAppNumber`), never `items`. Tenant creation (BOTH `TenantService.createTenant` + `create-tenant`) seeds `LBP` currency (`decimals 0`, symbol `ل.ل`), `rate_per_usd` from `LiraRate` (fallback `DEFAULT_LIRA_RATE = 89000` if missing/invalid); one-time start value, not live link. Keys immutable; use `OPTION_KEYS`.
39. **Keyboard avoidance = `react-native-keyboard-controller`, never RN's `KeyboardAvoidingView`** — `app.json` `edgeToEdgeEnabled: true` (SDK 54 default) → Android window doesn't resize, RN `KeyboardAvoidingView` (`behavior="height"`) shrinks nothing, lower fields of long form stay under keyboard (shows on real devices/release APKs, not always dev). One `<KeyboardProvider>` in `SubsTrack/app/_layout.tsx` (inside `GestureHandlerRootView`).
    - Plain full-scroll screens (`LoginScreen`, non-sheet forms) → `<KeyboardAwareScrollView … bottomOffset={24}>`. Sheets excluded: every `*FormSheet` uses `FormSheet` since Gorhom migration (#45) (`BottomSheetScrollView` + `BottomSheetTextInput` via `AppTextInput`, #45), Gorhom owns keyboard (`keyboardBehavior="interactive"`).
    - Sticky-footer layouts (two signup screens: inner `ScrollView` + sibling footer) → library `<KeyboardAvoidingView behavior="padding">` (`KeyboardAwareScrollView` detaches footer).
    - Works inside RN `<Modal presentationStyle="pageSheet">` (≥1.13 added Android Modal support; iOS always worked), no nested provider. Native module (peer `react-native-reanimated` already installed; autolinked, no `app.json` config plugin): adding = **dev/EAS rebuild**, not hot-reloadable, not Expo Go ("Running the Apps"). NativeWind `className` works on these components via `jsxImportSource: 'nativewind'` transform.
    - iOS caveat (verify on device): `KeyboardAwareScrollView` inside `.pageSheet` has documented flicker history (https://github.com/kirillzyusko/react-native-keyboard-controller/issues/726); form sheets use `<Modal presentationStyle="pageSheet">`; Android unaffected. If flickers → library `<KeyboardAvoidingView behavior="padding">` (or `mode="insets"`); smoke-test before shipping iOS.
40. **Edge-function errors must be parsed, not passed to `handleError`** — `supabase.functions.invoke` collapses non-2xx into generic `FunctionsHttpError` (`"Edge Function returned a non-2xx status code"`). Real message = JSON body of the `Response` the error carries (error's `.message` is useless); functions-js v2 throws `new FunctionsHttpError(response)` → it is `error.context` **itself**, not `error.context.response`. `readFunctionsErrorBody` (`Shared/src/core/utils/functionsError.ts`) accepts **both** (whichever has `.clone()`); reading only nested one silently returned `null` for every error → phone showed bare "non-2xx" for a `create-user` rejection with a good body. Repos invoking edge fns (`UserRepository.create`/`delete`/`updatePassword`) call **`await this.handleFunctionsError(error)`** (`Shared/src/core/utils/BaseRepository.ts`), never `handleError` — surfaces server message (e.g. `"Forbidden: admins can only change passwords of staff users"`), generic fallback w/o body. `SignupRepository` uses `readFunctionsErrorBody` directly (needs `code`). New edge-fn call sites must follow. `create-user` rejections log structured JSON (`{fn, reqId, event, ...}`) via `log()`/`fail()`.
41. **Customer's plans live in `customer_plans` (service lines), not `customers.plan_id`**. `CustomerPlan` = one subscribed plan w/ own `start_date`/`cancelled_at`; `plan_id` may be NULL (custom line). **Plans managed inline in customer form** (`CustomerFormSheet` "Plans" section, create AND edit) — NOT from month-grid panel (line selector view-only). Save: form saves customer, then `customerPlans` slice's `syncLines(customerId, lines, removedIds, tenantId)` (`Shared/src/state/slices/customer-plans/customerPlanSlice.ts`) deletes removed, creates/updates rest, calls `get().customers.fetchCustomer(customerId)` so customer (single source of its lines) + grids refresh. **Remove** = `CustomerPlanService.deleteLine`: hard-delete if no payments, else soft-cancel (`active = false`) so history survives (rule #7). Form keeps **≥1 row** (plan-less row = custom amounts) → every customer has ≥1 line. Loads via `.select('*, customer_plans(*, plans(*))')` → `customer.customerPlans`. `payments.customer_plan_id` = structural link (which line a payment settles); `payments.plan_id` = price/plan **snapshot** (#2). Branch inherited from customer (no `customer_plans.branch_id`; `BRANCH_SCOPES.customer_plans = inherited`).
42. **Sale's collector cash = `amount_paid`, not `total_amount`** — sales revenue reports sum `total_amount` (sold); cash collector holds = `amount_paid` (partial leaves rest as debt). Collector Wallet reads `amount_paid` for sales, never `total_amount` (overstates by unpaid part). (`WalletService.collectItems` → `saleService.getHeldForWallet`)
43. **Re-paying a voided month must reset whole custody block** — payments upsert on `(customer_plan_id, billing_month)` → re-record **reuses row**; if it had travelled up the chain, new cash would inherit someone else's custody. All three columns written explicitly on re-pay: web `PaymentRepository.create`/`createMany` upsert object + offline `buildRow` set `held_by_user_id: <the collector>, remitted_at: null, remitted_by: null` (offline `ON CONFLICT DO UPDATE` copies via `excluded.*`). Wallet = **columns on row**, not link table (link keyed by reused id goes stale). `custom_debts` has **no** custody columns (not collected cash). Editing `amount_paid` does **not** touch custody → changes historical figure, not any current wallet.
44. **Back closes open sheet on Android** (browser-Back part retired — Expo web removed, H2)
    - Android hardware-back: **Gorhom does NOT handle it** (v5 no `BackHandler`; sheets aren't RN `Modal`s → no `onRequestClose`). Assuming otherwise was a real bug (Back popped route, sheet stayed). Fix: `useAndroidBackDismiss(active, onDismiss)` (`SubsTrack/src/shared/hooks/useAndroidBackDismiss.ts`), called by `AppBottomSheet` for **every** variant. RN fires `hardwareBackPress` **newest-first** → stacked sheet, or selection bar inside one (`useSelectionBackHandler`), dismisses first. Centered dialogs (`ConfirmDialog`, `UpgradePromptModal`) = plain RN `Modal`s → `onRequestClose`.
45. **Every sheet is a Gorhom bottom sheet; confirmations stay centered** — `@gorhom/bottom-sheet` v5, one core `AppBottomSheet` (`SubsTrack/src/shared/components/AppBottomSheet.tsx`) wrapping `BottomSheetModal` (`BottomSheetModalProvider` in `SubsTrack/app/_layout.tsx`); **bridges declarative `visible`/`onDismiss` to `present()`/`dismiss()`**. Tracks Gorhom's **real** open state via `onChange` (`openRef`). Dismiss handler: user close (caller still `visible=true`) → propagate; programmatic (`visible=false`) → swallow → `onDismiss` once. Drag-down + backdrop close from Gorhom (`BottomSheetBackdrop` `pressBehavior="close"`); Back by app (#44). No hand-rolled Reanimated sheet, `animationType` instant-close hack, `wrap` prop; sheets always edge-to-edge (web 768px cap retired with Expo web, H2); Gorhom owns keyboard (`keyboardBehavior="interactive"` + `android_keyboardInputMode="adjustPan"`). **`android_keyboardInputMode` must NOT be `adjustResize`**: tells Gorhom "window self-resizes, stay out" → Gorhom sets `keyboardHeightWithinContainer = 0` and returns; untrue (`edgeToEdgeEnabled: true`, #39) → sheet kept 92% height, bottom under keyboard, **last fields of long form unscrollable**. `adjustPan` (Gorhom default) lets its `interactive` handling shrink content box to space above keyboard. No native rebuild needed (Gorhom rides on already-native `react-native-reanimated` + `react-native-gesture-handler`). Variants:
    - `BottomSheetScaffold` (`variant="auto"`, `enableDynamicSizing`, capped by `maxDynamicContentSize`) — every transient popup: `Dropdown`/`DropdownModal`, `DatePickerInput`, `CurrencyInput`, `AsyncEntityPicker`, `ActionMenu`. **Always mounted**, toggle `visible` → `visible=false` passes before first open, and after each gesture close `visible=true → onDismiss → visible=false`. `present()`/`dismiss()` **out of sync w/ real state wedges sheet** (next call silently no-ops) — made pickers never open, then open only once. Fix: `openRef` from `onChange` gates **both** (`present()` only when `!openRef`, `dismiss()` only when `openRef`) → idempotent; new always-mounted sheets inherit. Long list: pass **`scrollable`** (only `AsyncEntityPicker`) → FIXED snap `70%`, `flex:1` body, list `flex:1` not `maxHeight`. Short lists (`Dropdown`, `CurrencyInput`) + fixed-height content (`DatePickerInput` columns) keep dynamic sizing w/ `maxHeight` → 2-item list hugs content, not ballooning to 70%. Dynamically-sized body → PLAIN RN scrollables only (#47).
    - `FormSheet` (`SubsTrack/src/shared/components/FormSheet.tsx`, `variant="full"` `~92%` snap) — every form/detail sheet; owns chrome (handle, title + one dismiss action, `BottomSheetScrollView` body in `ResponsiveContainer`).
