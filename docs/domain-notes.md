# Domain Notes — core model + feature summaries

Full prose per topic; AGENTS.md §6 keeps a one-line short form of each Core model rule. Deeper: `docs/features.md` (behavior), `docs/gotchas.md` (traps).

## Core model — full text (AGENTS.md §6 short form)

Domain types (camelCase) `Shared/src/core/types/index.ts`; DB rows (snake_case) `Shared/src/core/types/db.ts`, **never leave repositories**. Source files authoritative for shapes. Columns/constraints: `docs/db-schema.md`.

**The Ledger** (replaced `payments` + `custom_debts` + `debt_payments` outright — `amount_paid` held one number + one date, so a second payment had nowhere to go):
- **`charges`** = what is OWED (kind `month`|`sale`|`manual`), amount frozen. `paid` never a column — `SUM(collection_items)`, the `charge_balances` view (same GROUP BY offline). Makes collecting offline-safe: a counter gets clobbered, additive item rows merge.
- **`collections`** = ONE physical cash hand-over. **One currency per hand-over**, = every charge it pays → `collection_items` has no currency; "collect all due" can be two writes for one customer (gotcha #108). Collect sheet still shows **every** currency owed at once — one box per currency, typed in its OWN units, **never converted**; `collectMulti` turns one Save into one row per currency (gotcha #108b). Holds the only custody in the schema (`held_by_user_id`, `remitted_at`/`remitted_by`).
- **`collection_items`** = which bill each slice of a hand-over paid.
- **Waterfall** (`ledger/utils/waterfall.ts`, pure): fills bills **oldest `due_date` first, each completely** — never proportionally. 4-level sort (`dueDate → issuedAt → createdAt → key`) so preview = save and two devices split identically. Leftover = overpay → refused. The order is **shown**, not just applied.
- **A month has no bill until money reaches it.** `LedgerService.getOwed` merges stored charges with virtual unpaid months, deduped on `(customer_plan_id, billing_month)`: PAID stored bill wins; EMPTY bill loses to the virtual month, priced at THAT month's price (gotchas #106b, #185). Collecting materializes the bill with `deterministicId(line, month)` → two offline devices converge on ONE row.
- **OWED vs DEBT**: owed = everything with a balance (waterfall input, incl. unpaid months); debt = subset, `isDebtItem(kind, paid) = kind !== 'month' || paid > 0`. **A fully unpaid month is OWED, NOT a debt.** **To collect page** (was Debts; `/debts`, phone Transactions tab) lists OWED: `ledgerService.getOwedView` → `owedItems()` (`collectTotal.ts`) → `buildOwedView` = the SAME items the dashboard **Total to collect** sums (#184); filter All / Debts / Unpaid months = `showOwed` view; Debts filter = stored bills only (`buildDebtsView`, #106c). Every per-customer money figure (card pill, web column, `owes` filter, `to_collect` sort) = To collect, computed on the server too (`toCollectByCustomer`, gotcha #193). One customer = `ledgerService.getToCollect` → `customerOwedEntry` via Shared `useCustomerToCollect` (customer page panel both apps, web Customers amount link). Debt-only: dashboard **Debts** tile, Reports Debts, Write off all. Code: `transaction/to-collect/` = owed (page, `Owed*` rows, `OwingCustomer*`), `transaction/debts/` = debts only (custom debt, history, written-off).
- **Void vs write-off**, exclusive via `chk_charges_void_xor_write_off`: void = bill was a MISTAKE; write-off = REAL but lost. **Either leaves a dead bill that still owns its month** (gotcha #115) → a write **revives before it collects**: `reviveTargetBill(s)` clears all six void/write-off columns unconditionally whenever money arrives. **A never-paid month is written off by raising its bill ALREADY written off** (`ChargeService.writeOffOwed`, deterministic id → one row across phones, month's own price; gotcha #186). Debtor "Write off all" = debts only; customer "Write off everything" = debts + unpaid months. **Written-off bill stays REACHABLE, write-off undoable** (gotcha #152): reads take `writeOffScope` (`'live'` default); written-off bills = SEPARATE per-customer read, never in `DebtsView` or any total; `ChargeService.revertWriteOff` clears only the three write-off columns — not a revive, so the trail says "undid the write-off", not "re-opened".
- Reading owed = **ONE query** `ChargeRepository.findOpenWithPaid` (gotcha #118). A write **returns what it WROTE** (gotcha #119).
- **Two void doors** (gotcha #109): voiding a **payment** = that hand-over was wrong, bill stays owed (in `BillPaymentsList`, no order gate); voiding the **bill** = should never have existed, cash goes too — `ChargeService.voidChargeWithPayments`, payments voided **first**. Confirm always says the money goes and names other bills it un-pays (gotcha #125). Plain `voidCharge` still refuses a paid bill. A **month** bill void gated NEWEST-FIRST via `payments.voidMonthBill`. Hand-overs voided in ONE write (`CollectionRepository.voidMany`), never a loop.
- **Correct amount** (mistyped payment) = void + re-recorded hand-over in ONE call, `CollectionService.correct` → `ICollectionRepository.replace` (gotcha #171): same date, collector, currency, rate, notes, **custody**; only amount + its split over the SAME bills change. Any rebuilt hand-over (`unpayCharge` too) goes through `replace` keeping custody — a fresh `create` would put handed-over cash back in the collector's wallet.
- Line with **no set price** → collected through an OPEN item (gotcha #112): the collect sheet's "Amount for this month" field IS the bill and picks the currency; flag `OpenItem.openAmount`.

Types to know: `Charge`, `Collection`, `CollectionItem`, `ChargeBalance`, `MonthBill`, `OpenItem`, `AllocationLine`, `CustomerDebts`, `DebtSummary`, `CollectionListItem`, `CollectedRow`/`CashRow`, `ReportPeriod`, `DashboardMetrics`, `Customer`, `CustomerPlan`, `Plan`, `Product`, `Service`, `SaleItem`, `StockMovement`, `Expense`/`ExpenseItem`/`ExpenseSummary`, `SkippedMonth`, `MonthEntry`, `TenantSetting`, `UnpaidStartRule`, `Branch`, `Tenant`, `Currency`, `CustomerRequest`, `AuthUser`/`AppUser`, `UserRole`, `MonthStatus`, `ChargeKind`, `SaleLineType`, wallet: `WalletItem`, `UserWallet`, `UserWalletDetail`, `WalletSource`, `ReceiveBlock`.

Easy-to-get-wrong facts:
- **Dashboard revenue = CASH COLLECTED, never billed value** — one source: `collection_items`, scoped by `collections.received_at`, summed in USD via the collection's frozen rate. Read returns one row per **BILL SETTLED**, not per hand-over (gotcha #107) — that makes the streams add up exactly. Never switch back to `sales.total_amount` or `charges.amount`; `paymentsCollectedCount` = **distinct `collectionId`s**.
- **Product stock computed at runtime** — `SUM(stock_movements.quantity_delta)` over non-voided rows, never a stored counter. Manual entry only ADDS; mistakes fixed on the entry (**Edit entry**/**Revert entry**, gotchas #94/#96). A sale appends one negative `'sale'` movement per line inside its own write; voiding a sale **soft-voids** those rows, never inserts opposites. Oversell blocked in `SaleService.createSale` (advisory — two offline devices can each sell the last unit).
- **Sale = header (`sales`) + lines (`sale_items`)**, holds **no money**: owes via its `charges` row, collected via `collections` rows → installments possible. A line sells a **product OR a service**; service = labour, **no stock, cost or quantity** (always 1 via `lineQuantity()`), **never a separate money stream**. Stock paths narrow via `productLines()`/`savedProductLines()`, never a nullable-id test (gotcha #97). Editing a sale touches three tables with three rules (gotcha #90). Collected amount is an ABSOLUTE input on the edit form; lowering it **rebuilds** cash — void every live hand-over, re-create slices that paid other bills, re-record the new figure at the ORIGINAL date + collector. Never an edited payment, always void + write (#111).
- **A sale's total is TYPED; lines only SUGGEST it** (gotcha #142). `SaleService.totalOf(input)` = `input.totalAmount ?? lineSumOf(items)` is the one place money is decided — header, bill, every cap read it; nothing writing money may call `lineSumOf`. Line prices never rewritten to match → a receipt may not add up (= the discount). A sale may have **ZERO** lines: `validate` guards a positive TOTAL, not a non-empty cart; `items_summary` falls back to `sales.no_items_summary`. Save always **confirms** a total ≠ line sum, never refuses (no rule tells a discount from a typo).
- **Sale identity = RECEIPT NUMBER** — last 6 chars of `id` uppercased, `receiptId()` in `Shared/src/core/utils/receiptId.ts`. **No sequence column, must not be one** (offline device raises a sale with no server round trip). It is the sale card **title** (items summary → subtitle), receipt "Receipt ID" row, History sheet header (both entry points pass `saleTitle()`), and via `chargeLabel` every place a sale bill is named: money-received card + payment details sheet, debts, collect preview, WhatsApp — on that ledger path the ONLY identity (`charges(*)` never joins `sales`; the label used to be bare "Sale"). Audit Log card chip stays the **customer** (the subject, not the record name). **Search is the one platform difference**: native matches the id tail in the mirror (SQLite `id` is TEXT); web filters `receipt_id(sales)`, a PostgREST **computed field** storing nothing — Postgres has no `ILIKE` for `uuid` and PostgREST won't cast a filter's left side, so `id.ilike` / `id::text.ilike` can never work. A term is a receipt number only if short + hex (`isReceiptIdTerm`); the clause is **OR'd onto** the item/customer search, never replacing it. One search helper per repository, shared by `findAll` + `monthlyTotals`, so a page and its total can't disagree.
- **PostgREST `or()` may only name columns of the queried table.** A dotted embed path (`customers.name.ilike…`) → 400 _"failed to parse logic tree"_, so sales search resolves matching customers in a **pre-query** and ORs `customer_id.in.(…)` (the product filter's shape). **Never `customers!inner`** — makes the embed filterable but INNER-joins away every WALK-IN sale. Offline needs none: SQL ORs `c.name` over its LEFT JOIN. Every typed term → `sanitizeSearchTerm()` (`Shared/src/core/utils/searchTerm.ts`), strips `, ( ) % * \` — one unescaped `%` breaks the logic tree and 400s the whole list.
- **Expenses = stored `expenses` rows + DERIVED stock purchases** (read-time from `stock_movements.unit_cost × quantity_delta`). A restock **never** writes an expense row → a derived row can't be voided, fix the movement. Cash basis, like revenue. Admin-only. Both halves branch-`owned`, so branch views SUM to the tenant total (gotchas #88/#89).
- **A line's price = `resolveLinePrice(line)`, NEVER `plan.price`** — amount, currency and `durationMonths` travel together, else an LBP amount freezes at a USD rate of 1 (gotcha #85).
- **A MONTH's price = `linePriceAt(line, month, history)`** (`customer-plans/utils/priceHistory.ts`), never today's (gotcha #185). Append-only `plan_price_changes` (price, currency, months covered) + `line_price_changes` (the line's **special price** + currency ONLY) each say "this price from `from_month`"; latest edit reaching a month wins; `from_month NULL` = price before the first edit; no rows = today's price. A month with a special price (per the line's history) takes it; else the line's **current** plan as priced that month (plan history) — a line's old plan is never read. Every past-month reader (`mergeOwed`, grid `priceAt`) takes a `PriceHistory` from `priceHistoryService.getForLines`; current-month readers keep `resolveLinePrice`. An edit records BEFORE the plan/line row moves; the form's "New price starts from" picker (shown only when a saved plan price / special price changed) picks the month — current or up to 11 back, never future. A line **plan switch** writes no history and never asks; only a line no money reached may switch. A month money reached keeps its bill amount (rule 8).
- **Collector wallet + custody chain** computed at runtime from non-voided `collections.held_by_user_id`. Cash moves **UP** (collector → branch admin → tenant-wide admin → owner), never sideways. Rules in one pure file `modules/wallet/utils/custody.ts` — **never derive a wallet permission from `role` alone** (can't tell branch admin from tenant-wide).
- **Audit trail written by the APP, never a Postgres trigger** (a trigger stamps the sync moment + syncing session). Append-only, admin-only reads, server-first with un-pushed local rows merged in. `stock_movements` audited for **changes only**.
- **Reports** aggregate in memory from one read per window, **re-implement no rule**. **No charts** — never reintroduce a charting library. Period scopes the CASH, never the debt (gotcha #91).

## Feature notes

> **Sales.** `products` + `services` + `sales` = one-off selling. Header (`sales`) holds the one sale-wide currency + frozen rate, app-written `total_amount` (TYPED, #142: form seeds it from lines, re-seeds on any line change, staff may overwrite), frozen `items_summary` (search + list/debt/wallet labels; generic word when zero lines). `Sale` / `SaleItem` in `Shared/src/core/types`. → `docs/features.md` → Products & One-Off Sales.

> **Services.** A sale may hold product lines, service lines or both (orig.: at least one line of some kind). Service = labour (installation, repair visit): no stock, no cost → never an expense, **never a separate money stream** (#98 — a mixed sale's cash can't be split; Reports keeps ONE "Sales" stream; partly-paid sale = one `sale` charge). `sale_items`: `line_type` + nullable `product_id` / `service_id` (`chk_sale_items_line_ref`); name column `item_name_snapshot` (renamed from `product_name_snapshot`, #99). Staff pick from admin price list (`services`, Admin → Services = products screen minus stock + cost, uncapped by tier) **or** type a one-off line (`service_id IS NULL`). Stock paths narrow via `productLines()` / `savedProductLines()` (`sales/utils/saleLines.ts`), never a nullable-id test (#97). No quantity, only a price (#100): `service` variant of `CreateSaleItemInput` has no `quantity` (compiler enforces, no DB check), `sale_items.quantity` stores 1, read via `lineQuantity()`; one **Price** field, no stepper; receipt + WhatsApp drop `1 × …`. Kind = which footer button added the line (**+ Add product** / **+ Add service**); card only labels it; new sale opens w/ zero rows; any row incl. last removable (= how kind changes); never a page-level control in a form card (per-row `Product | Service` `SegmentedTabs` read as page tabs + wiped the line, #101). No Transactions → Services tab (Sales tab lists them). → `docs/features.md` → … → Services; traps #97–#101.

> **Product stock.** `Product.stockOnHand = SUM(stock_movements.quantity_delta)` (non-voided): view `product_stock` on web, `GROUP BY` on mirror. Every product tracked. Sale's `'sale'` movements written in the sale's own write (offline: same transaction); void soft-voids them → repeat void can't return stock twice. Stock added via product's **stock sheet** (one `'restock'` row per save, optional cost, note + history), never by typing a total; no remove-from-stock form; damaged/lost/returned stock has no door. **Batch restock sheet** (`ProductService.restockMany`, from products screen + quick-actions menu) = one `'restock'` row per product. Oversell block in `SaleService.createSale` is advisory (#48). → `docs/features.md` → Products & One-Off Sales.

> **Editing / reverting a manual stock entry** — all rules → #96. Doors: **Edit entry** (`ProductService.updateMovement`; stock sheet history row menu; same sheet form doubles as edit form) and **Revert entry** (`ProductService.revertMovement`, soft-void `voided_at`/`voided_by`, row stays w/ "Reversed" chip); both fix the entry's OWN month; Remove mode is gone. Editable: quantity, cost + currency, note. Locked: `occurred_at`, `reason`, `product_id`, `'sale'` + voided rows (refused in the service via `liveManualMovement()`). Quantity = magnitude, sign from existing row; rate re-freezes only when cost moved; oversell warned, never blocked. Reverted row's menu = **History** only. Audited for changes only, under parent product's `branch_id` + name via `auditedUpdate`'s `audit` option → `audit_logs.subject` can be a product (`subjectLabel()`). No schema change (`updated_at` already synced) → OTA.

> **Receipt number** — Core model above holds it all (`receiptId()`, no sequence column, `chargeLabel` surfaces, `receipt_id(sales)` search, `isReceiptIdTerm`). Extra: printed `#A1B2C3`; also on the WhatsApp receipt and the collect sheet's shared-bills warning.

> **Sale row menu** — View receipt · Edit sale · **Collect** (only while owing + w/ a customer) · Send invoice on WhatsApp · History · Void sale; voided → view + history. Defined once in `sales/hooks/useSaleActions.tsx` for all three sale surfaces (Sales tab, customer panel, per-customer page); hook owns `ActionMenu`, the shared-reason void dialog (`SaleBulkVoidSheet`, same as multi-select toolbar → one path) and history sheet; screens keep receipt + form. Voiding a paid sale is allowed and takes its payments (cash was handed over _for_ it); confirm says so, no count, names other bills a shared hand-over un-pays (#125). One menu per **screen**, not per card (lists virtualized + paginated; unlike debts/expenses cards). Receipt sheet header carries Edit sale · History · Void sale (`FormSheet`'s `menuActions`, #131); body keeps only the green WhatsApp button. Receipt lists every payment on the sale via shared `BillPaymentsList` fed `sale.chargeId` (one row per hand-over: date, collector, own void). → `docs/features.md` → … → Row actions.

> **Voided sales on the Sales tab**, behind the Status filter `sales.status` (`live` | `voided` | null = "Live and voided", default) — a voided sale's only door onto that list. Reuses collections filter's `includeVoided` / `voidedOnly` on `FindSalesOptions` (both repositories). `SaleCard` marks it (dimmed, struck-through amount, red **VOIDED** chip w/ reason); selection toolbar's **Void** skips such rows. **Month section totals never count a voided sale** (it sold nothing): `monthlyTotals` returns nothing under "Voided only", live rows otherwise — only screen where a header may read less than its rows. `applyVoidedSales(items, voided, keepVoided)` (`sales/utils/saleListPatch.ts`) keeps a just-voided row in place, marked, when the status admits voided rows, else drops it (else the record vanishes from a list meant to show it).

> **Editing a sale** (`SaleService.updateSale`; row menu or receipt "Edit sale" on all three surfaces; **any staff member**, **never** a voided sale). One form: `SaleFormSheet` w/ optional `sale` prop. Changeable: lines (incl. product ↔ service), quantities, unit prices, currency (re-freezes `rate_per_usd_snapshot`), customer, notes. Fixed: `id` / `tenant_id` / `sold_at` / original `recorded_by_user_id`. Collected = absolute `UpdateSaleInput.collectedTotal` capped at typed total; raise = one extra hand-over dated today; lower / currency move on a paid sale = rebuild via `collectionService.unpayCharge` → #111. Three tables, three rules (dropped line soft-voided `sale_items.voided_at`, filtered in `mapDbSaleToSale`; lines matched by position; movements swapped only when unit count changed, like `voidSale`; own units credited back; walk-in keeps `sale.branchId` not `user.branchId`; no custody lock) → #90. One `'update'` audit entry per sale. Sale's bill rides in `CreateSalePayload`, till cash via normal collect → #110.

Debtor sheet + customer Transactions panel have **Owed now / Written off** `PillTabs` (customer list's filter control, default "Owed now"; written-off read fires only when that tab picked), read separately from `DebtsView`; such rows offer only **Undo write-off** (`ChargeService.revertWriteOff`: clears 3 write-off columns, keeps `issued_at` + money, NOT a revive → audit "undid the write-off"). No surface COUNTS payments; payment void needs no read (split on row); month-bill + sale doors read hand-overs once before the confirm to name bills; write takes its own ids (`paymentIdsForCharge`, `paymentIdsForCharges` for a sale selection).

Money in currency PHYSICALLY handed over (`formatMoneyPair`, #128), `≈` display line only when different; month section headers still convert. Chrome: shared `PeriodPicker` (visible chip, never silent one-month default) + chips customer, collector, **type**, **status**, **sort by**, **order**; one summary bar over slice's unpaginated `monthlyTotals` (all matching rows). Status + sort = `voidedOnly` / `sortField` + `sortDirection`, server-side in both repositories. Sort only dates the hand-over OWNS (received — back-datable, recorded, last-updated); no due-date or amount sort; offline field whitelisted; `created_at` tiebreak (#129). Tap opens what it settled; voided row opens too, always the split (its bill is owed again, not that row's story). `CollectionSplitSheet` = whole record (customer · received · taken by · where cash is now · **notes** · void time + reason); each bill card shows the **bill's** total, due date, billing instant — never remaining balance (`BillSheet`'s job). `BillSheet` same depth, in the **bill's own currency**.

> **Dashboard revenue** (rules in Core model above, #107): a partial adds only what arrived; the rest enters revenue in the month collected → each amount counted once. One row per bill settled makes `subscriptionRevenue + salesRevenue + manualRevenue` = `monthlyRevenue` exactly (old 3-stream model put sale-debt cash in a "debts" bucket). `salesCount` still counts sale rows (`SaleRepository.countInRange`); only money is cash-based. → `docs/features.md` → … → Dashboard.

> **Expenses** (Transactions → Expenses, **admin-only**; + "Add expense" quick action) = money OUT → real net. `ExpenseService.getExpensesView({ startIso, endExclusiveIso, branchFilter })` composes (like `LedgerService`): stored `expenses` rows (rent, salaries, fuel…) + derived `stock_movements.unit_cost × quantity_delta` over costed, non-voided, non-`'sale'` rows. Restock never writes an expense row (no dual write, no orphan on cascade) → derived row can't be voided, card offers "Open product" (#89). Stock expense comes down only via the entry's **Edit entry** / **Revert entry**, in that entry's own month (#96); no Remove mode. Credit arithmetic (`amount = quantity_delta × unit_cost`) kept for older negative rows; editing one still shows credit in green; every figure via `outflowLabel()` (`+` for credit, else `−-$5.00`) (#94). Cash basis (#89): month PAID FOR; correction lands in the entry's month (July delivery fixed in August moves July). `ProductService.movement()` = only writer of `unit_cost` + `currency_id` + `rate_per_usd_snapshot` (together or all null), refuses a cost only on `'sale'`. Cost typed in: product form (**Cost price** pre-fill default + opening stock cost); stock sheet — **Cost per unit** + **Total cost** side by side, each fills the other from quantity; only `unit_cost` saved (8 decimals, so expense = typed invoice); **last field typed = anchor**, a later quantity fix recomputes the other; batch restock (one **delivery currency** per save, rows seeded from product cost). Dashboard: `monthlyRevenue` stays GROSS, `netIncome` subtracts (keeps `prevMonthRevenue` + pill meaning); hero gets orange `Expenses −$X` chip + Net line + two full-width tiles; gate reuses wallet's `viewer`. **Branch trap: both halves `owned` so branch views SUM to tenant** → #88 (`expenses.branch_id NULL` = company, all-branches view only, alone via Unassigned chip; `stock_movements: { kind: 'inherited', joinedTable: 'products' }`; never `shared`). `Expense` / `ExpenseCategory` / `ExpenseItem` / `ExpenseSummary` / `ExpensesView` in `Shared/src/core/types`. → `docs/features.md` → Expenses; traps #88, #89, #94, #96.

> **Reports** (bottom tab, **admin-only** `href: isAdmin ? undefined : null`, same gate as Expenses + dashboard): business over **any** period (Home = this month). Curated sections, never a free query builder; web adds filters + group-by + drill per section (Overview, Money in/out, Debts, Customers, Sales, Staff) over the same in-memory rows (`reports/utils/analysis.ts`, `docs/features.md` → Web Reports).
