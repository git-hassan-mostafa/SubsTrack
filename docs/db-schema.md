# Database Schema Reference

Per-table column notes + key constraints. Authoritative DDL = `sql scripts/script.sql`; SQLite mirror = `SubsTrack/src/core/offline/db/tables.ts`.

### Database Schema (Supabase PostgreSQL)

- **`tenants`**: `id`, `name`, `tenant_code`, `active`, `customer_allowance`, `plan_allowance`, `price_per_plan_usd`. Last three = what the SaaS owner charges for, **owner-only**: no UPDATE policy on table; `trg_tenants_guard_billing` raises if any authenticated session changes any of them; only service role (SuperAdmin, Edge Functions) writes them. **Bill counted on `plan_allowance`'s unit** (active service lines, not customers); `price_per_customer_usd` renamed → `price_per_plan_usd` (carry-over + drop in `migration.sql`). `chk_tenants_plan_allowance_floor` holds `plan_allowance >= customer_allowance`; live DB must run `migration.sql` first to lift every tenant to `GREATEST(plan_allowance, customer_allowance, its active line count)`, else constraint refused. ONE tenant-side door: `lower_allowances(p_customer_allowance, p_plan_allowance)` — SECURITY DEFINER, admin-only, **both limits in one call**, only ever LOWERS: RAISEs on either arg above current value, nothing moving, line limit < customer limit, anything < product floor **30**, anything < tenant's live counts of active customers / active lines (reads them itself, never from client). Active line = line active **and its customer active**. `chk_tenants_customer_allowance_min` holds the 30 floor at the column.
- **`customer_requests`**: `id`, `tenant_id`, `requested_count`, `requested_plans`, `granted_count`, `granted_plans`, `status` (`pending`/`accepted`/`declined`/`cancelled`), `requested_by`, `decided_by`, `decided_at` — tenant admin asks owner for more customer slots, line slots, or both. Either half may be 0; ten-slot minimum binds the **total** (`chk_customer_requests_total_min`, replaced single-column `chk_customer_requests_min`, dropped in `migration.sql`). `uq_customer_requests_one_pending` = **partial** unique index on `(tenant_id) WHERE status = 'pending'` → one open at a time. RLS: every member SELECTs; admins INSERT (born pending, undecided) and UPDATE only still-pending rows, to `pending` (edit) or `cancelled` — never `accepted`. Accept = `accept_customer_request(request_id, granted, granted_plans)`, SECURITY DEFINER, REVOKEd from `anon`/`authenticated`; closes request + raises both allowances in one call so writes can't tear; line limit takes `GREATEST(plan_allowance + granted_plans, customer_allowance + granted)` to keep floor invariant. Two-arg version dropped by signature in `migration.sql` (a live overload would keep answering). **Not mirrored offline** → `docs/offline.md`.
- **`app_options`**: `id`, `key` (unique), `value`, `description`, `created_at`, `updated_at` — **global** key/value config (e.g. `LiraRate`, `AllowSelfServiceSignup`, `SupportWhatsAppNumber`); NOT tenant-scoped. SuperAdmin writes (service role); read by **anon + authenticated** (anon b/c some flags gate pre-auth UI). Fetched at app bootstrap (not only post-auth), intentionally **not** reset on logout. Read via typed hooks in `useOptionSlice.ts` (`useOptionValue` / `useBooleanOption` / `useCanUpgradePlan` / `useSelfServiceSignupEnabled` / `useSupportWhatsAppNumber`); conditional UI → gate components `<CanUpgrade>` / `<CanCreateOrganization>` from `shared/components/FeatureGate.tsx`; keys in `OPTION_KEYS`.
- **`tenant_settings`**: `id`, `tenant_id`, `key`, `value`, `created_at`, `updated_at` — **per-tenant** twin of `app_options`. `UNIQUE(tenant_id, key)` (also offline deterministic-id natural key). RLS: every member SELECTs, **admins only** write. Synced like any tenant table. Keys in `TENANT_SETTING_KEYS`; read via `useTenantSettingSlice` / `useUnpaidStartRule` / `useDisplayCurrencyId`. Keys: `UnpaidStartRule` (`month_start` \| `customer_start_day`), `DisplayCurrencyId` (a `currencies.id`; blank/unset = USD).
- **`currencies`**: `id`, `tenant_id`, `code`, `name`, `symbol`, `rate_per_usd`, `decimals`, `active`.
- **`branches`**: `id`, `tenant_id`, `name`, `active`.
- **`users`**: `id` (= auth.users.id), `username`, `full_name`, `phone_number`, `role`, `active`, `tenant_id`, `branch_id` (NULL = tenant-wide = belongs to every branch, not "unassigned"). RLS **asymmetric on purpose**: `users_select` branch-**shared** (own branch + every `branch_id IS NULL` row, so tenant-wide admins + owner have a name wherever money is attributed); `users_insert` / `users_update` branch-**owned**. → gotcha #147.
- **`plans`**: `id`, `name`, `price`, `is_custom_price`, `duration_months`, `currency_id`, `branch_id`, `tenant_id`.
- **`customers`**: `id`, `name`, `phone_number`, `address`, `area`, `notes`, `location_url` (raw Google Maps share link, nullable), `active`, `is_regular`, `branch_id`, `tenant_id`, `cancelled_at`, `portal_password`, `portal_enabled`. NO `plan_id`, NO `start_date` — plans + the only start dates live in `customer_plans`. `portal_*` gate the read-only customer portal; NO link-code column (link IS `{CustomerPortalUrl}/{id}`). `portal_password` PLAIN TEXT on purpose (staff read it back to a customer who forgot it, and set it offline) → excluded from audit trail via `IGNORED_FIELDS`, never returned by portal endpoint.
- **`customer_portal_lockouts`**: `customer_id` (PK), `failed_count`, `first_failed_at`, `locked_until`, `updated_at` — brute-force throttle for public `customer-portal` edge function. RLS on with **no policy** (service_role only, same idiom as `app_options` writes). Deliberately **not** tenant-scoped, **not** in `tables.ts`, **not** in `PUSH_WAVES`: a failed-login counter must never enter the sync engine.
- **`customer_plans`**: `id`, `customer_id`, `plan_id` (null = custom/occasional line), `start_date`, `cancelled_at`, `active`, `custom_price` + `custom_currency_id` (line's own **special price**, replacing plan's; NULL = use plan's; NULL currency = USD), `tenant_id` — **one service line per row**; customer may hold several, each paid independently. No own `branch_id` (RLS inherits customer's).
- **`charges`**: `id`, `tenant_id`, `branch_id` (own; read only for walk-in sale, else branch = customer's), `customer_id`, `kind` (`month`\|`sale`\|`manual`), `customer_plan_id` + `billing_month` + `duration_months` + `plan_id` (month), `sale_id` (sale), `description` (manual), `amount`, `currency_id`, `rate_per_usd_snapshot`, `issued_at`, `due_date`, `recorded_by_user_id`, `notes`, `voided_at`/`voided_by`/`void_reason`, `written_off_at`/`written_off_by`/`write_off_reason`. **What is OWED.** `paid` never a column = `SUM(collection_items)`, exposed as `charge_balances` view, which also carries bill's `branch_id` / `customer_id` / `customer_plan_id` / `kind` / `due_date` / `written_off_at` / `created_at` / `updated_at` (last two only for debt-history sort) → "which bills still owe?" is a server-side filter, not client id list (gotcha #118). `chk_charges_kind_ref` keeps each kind's columns honest; `chk_charges_void_xor_write_off` keeps mistake vs loss exclusive.
- **`collections`**: `id`, `tenant_id`, `branch_id`, `customer_id`, `amount`, `currency_id`, `rate_per_usd_snapshot`, `received_at`, `received_by_user_id`, `notes`, `kind` (what the cash PAID FOR — the one kind all its items share, or `mixed`; **frozen by app at collect time** like `sales.items_summary`, b/c COUNT(DISTINCT) over items is no server filter — gotcha #128), `voided_at`/`voided_by`/`void_reason`, `held_by_user_id` (who holds cash now; NULL = nobody) + `remitted_at` / `remitted_by` (cash left the chain). **ONE physical hand-over**; only table carrying wallet custody.
- **`collection_items`**: `id`, `tenant_id`, `collection_id`, `charge_id`, `amount`. Which bill each slice of a hand-over paid. **No currency of its own** — parent collection's, which must equal charge's → balance closes at exactly zero. `UNIQUE(collection_id, charge_id)`.
- **`expenses`**: `id`, `tenant_id`, `branch_id` (**own**; NULL = company-wide), `category` (free text in DB — app owns code list, new category needs no migration), `description`, `amount`, `currency_id` (NULL = USD), `rate_per_usd_snapshot`, `recorded_by_user_id`, `incurred_at` (when money went OUT — user-picked, every month bucket keys off it), `notes`, `created_at`, `updated_at`, `voided_at`, `voided_by`, `void_reason`. Only **hand-typed** expenses; stock purchase cost DERIVED from `stock_movements.unit_cost`, never stored here. RLS: **admins only**, read + write. Soft-void only, **no edit** → row is its own history, table deliberately not audited.
- **`skipped_months`**: `id`, `tenant_id`, `customer_id`, `customer_plan_id`, `billing_month`, `skipped` (bool toggle; `false` = unskipped, row kept), `note`, `skipped_by_user_id` — **no money**. `UNIQUE(customer_plan_id, billing_month)` (same natural key as month `charges` → offline deterministic id, devices converge). Branch inherited from customer via RLS.
- **`audit_logs`**: `id`, `tenant_id`, `branch_id` (denormalized from row or parent; NULL = tenant-wide; **no FK on purpose** — `ON DELETE SET NULL` would blank the trail on branch delete), `table_name`, `record_id`, `action` (`create`\|`update`\|`delete`\|`void`\|`restore`), `before_data` / `after_data` / `changed` (JSONB; **edit stores only changed columns**), `label` (frozen one-liner), `subject` (frozen customer name = who the record belongs to), `subject_id` (same owner as id, frozen, never joined back — customer timeline filters on it), `actor_user_id`, `actor_username` (snapshot, survives user deletion), `occurred_at` (**device** clock = when staff acted, NOT sync time), `created_at`, `updated_at`. **Append-only, written by app — never a trigger** (trigger would stamp sync moment + syncing session; offline device would keep no history). RLS: SELECT **admins only** (branch-aware), INSERT **every tenant member**, **no UPDATE/DELETE policy** (service_role only). → `docs/features.md` → Audit Trail.

Also `products` + `services` + `sales` + `sale_items` + `stock_movements` (→ `docs/features.md` → Products & One-Off Sales):
- Sale = **header + lines**. `sales`: `items_summary`, `total_amount` (app-written sum, NOT generated), currency + rate snapshot, void — no money, no custody.
- `sale_items`: one row per **product OR service** (`sale_id`, `line_type`, nullable `product_id` / `service_id`, `item_name_snapshot`, `quantity`, `unit_amount`, `voided_at` — set only when an EDIT dropped the line); branch inherited from parent sale via RLS `EXISTS`, `ON DELETE CASCADE`; `chk_sale_items_line_ref` keeps type + two id columns agreeing.
- `services` = labour price list (`branch_id` NULL = SHARED, `name`, `description`, `price`, `currency_id`, `active`) — `products` block minus `cost_price` / `cost_currency_id` and minus stock, with `products`' RLS pair (`services_select` / `services_modify`) copied verbatim → any tenant member may add one from sale form.
- Product **and** service delete-reference counts key off `sale_items.product_id` / `.service_id`, deliberately count voided lines too (both FKs `ON DELETE RESTRICT`).
- `stock_movements` = product stock ledger (`product_id`, signed `quantity_delta`, `reason`, `sale_id`, `note`, `recorded_by_user_id`, `occurred_at`, soft-void); branch inherited from parent **product** w/ SHARED semantics (`OR p.branch_id IS NULL`) — **not** `sale_items`' owned semantics, else every shared product reads out of stock for a branch-scoped user. `product_stock` view (`security_invoker`) sums it.
- `charges` + `collections` + `collection_items` = money model (above).
- `exception_logs` (`id`, `tenant_id`, `user_id`, `username`, `source`, `message`, `stack`, `context`, `occurred_at`) = native-only, push-only crash/error log → `docs/offline.md` + Settings → Developer in `docs/features.md`.

**WhatsApp Cloud API tables** (server-only, never mirrored; written only by `whatsapp-*` Edge Functions; full design `docs/whatsapp.md`): `whatsapp_accounts` (one row per tenant + phone number, `status` connected / needs_attention / disconnected; partial unique indexes: one live account per tenant, one live tenant per phone number), `whatsapp_credentials` (AES-GCM token + PIN, **no RLS policy**), `whatsapp_connect_sessions` (SHA-256 of one-time signup links, **no policy**), `whatsapp_templates` (synced from Meta, `UNIQUE(account_id, name, language)`), `whatsapp_messages` (history + send queue; `UNIQUE(tenant_id, idempotency_key)`, `UNIQUE(wamid)`; `variables` cleared once Meta accepts), `whatsapp_opt_outs` (STOP / admin, soft-cleared). Admin SELECT policies only; `whatsapp_messages` branch-scoped on its `branch_id` snapshot. `tenants.whatsapp_enabled` owner-only (same guard as billing columns).

**Key constraints:**

- `UNIQUE(username, tenant_id)` on users
- `UNIQUE(tenant_id, branch_id, name)` on plans — same name can be "Shared" + branch-specific (NULLs unequal in PG)
- `UNIQUE(tenant_id, name)` on branches
- `UNIQUE(tenant_id, code)` on currencies; `code` enforced uppercase, not 'USD'
- `UNIQUE(tenant_id, branch_id, name)` on services — same shared-vs-branch rule as plans/products
- `UNIQUE(customer_plan_id, billing_month)` on charges — one BILL per **service line** per month (multi-line customer billed per line); natural key the deterministic id is hashed from. `UNIQUE(sale_id)` — one bill per sale. `UNIQUE(collection_id, charge_id)` on collection_items
- `plan_id` on customer_plans: `ON DELETE SET NULL` (line goes plan-less; history kept via `charges.plan_id` snapshot)
- `customer_id` on customer_plans / charges / collections: `ON DELETE CASCADE`; `customer_plan_id` on charges: `ON DELETE CASCADE`; `collection_id` / `charge_id` on collection_items: `ON DELETE CASCADE`
- `branch_id` on users / customers / plans: `ON DELETE SET NULL` (branch delete reverts records to "unassigned" / "shared")
- `currency_id` on plans, charges, collections: `ON DELETE RESTRICT` (soft-delete currencies via `active = false`)
- **No DB check `Σ collection_items ≤ charges.amount`** — server must accept whatever an offline device replays (same reason as no `on_hand >= 0` on `stock_movements`). Overpay refused in service
- `product_id` on stock_movements: `ON DELETE CASCADE` (never-sold product stays hard-deletable, takes its ledger); `quantity_delta <> 0`; `reason = 'sale'` requires `sale_id IS NOT NULL AND quantity_delta < 0`. **No `on_hand >= 0` check** — DB must accept offline replays
- `chk_sale_items_line_ref` on sale_items: `'product'` line → `product_id NOT NULL` + `service_id NULL`; `'service'` line → `product_id NULL`, **may** have NULL `service_id` (= one-off typed service)

### Functions read by edge functions

`customer_status_facts(p_branch_id UUID, p_unassigned BOOLEAN) RETURNS json` — `SECURITY INVOKER`, `STABLE`, granted to `authenticated` only. Compact read behind `customer-status` edge function: for customers in scope (branch filter like `applyBranchFilter` 'owned'), every line w/ its live month bills (`[billing_month, duration_months, amount, paid]`, `paid` from `charge_balances`) + skipped months, plus each open, not-written-off bill (`[customer_id, kind, balance, paid, rate_per_usd_snapshot]`). ONE `json` value so PostgREST's row cap never cuts it. Decides no rule → `docs/edge-functions.md`.
