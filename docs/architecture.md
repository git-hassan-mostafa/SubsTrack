# Architecture & State — full detail

Extends CLAUDE.md §4–§5 (layer rules, offline seam, state key rules live there and are not repeated). Only the extra detail is here.

## Architecture (MANDATORY)

Layers L1 Presentation → L2 State → L3 Services → L4 Repository → DB, L5 Core under all: as CLAUDE.md §5. Extras: L2 = one global store of per-feature slices in `Shared/src/state/slices/` (`immer`), read via per-slice hooks (`useCustomerSlice`, …); single-module state = module store. L4 `BaseRepository` holds the supabase client + `handleError()` / `handleFunctionsError()`.

### Where code lives — `Shared/` and the apps

- `Shared/src/` = L2–L5 incl. `I*Repository` interfaces, i18next instance + `en`/`ar` locales.
- Not a workspace b/c it would hoist native packages to `App/node_modules` (gotcha #53). Peers in `Shared/package.json`: `react`, `zustand`, `immer`, `i18next`, `react-i18next`, `@supabase/supabase-js` (+ same list as pinned `devDependencies`, for `tsc`/editor only). One runtime copy per consumer: Metro `watchFolders` + `resolver.nodeModulesPaths: [SubsTrack/node_modules]` + `blockList` for `Shared/node_modules`; Vite (Portal, later Web) `resolve.alias` + `resolve.dedupe` read from peer list; Jest `moduleNameMapper`.
- `configureShared(runtime)` (`Shared/src/core/runtime/runtime.ts`): `supabase`, `authStorageKey`, `repositories`, `ids` (`randomUUID` + `sha1Hex` + `randomBytes` — last for portal password, `core/utils/portalPassword.ts`; phone = expo-crypto, web = WebCrypto), `storage`, `actor()` (who an audit row names), `logException?`. `runtime()` throws until configured. `runtimeStorage` waits for `configureShared()` b/c Expo Router loads route files before root layout and `uiPrefStore`'s `persist` hydrates at creation. `configurePhone.ts` called from `app/_layout.tsx`; tests: `tests/helpers/configureRuntime.ts`. Portal's pure code never reads runtime → configures nothing.
- Shared also never imports a relative path leaving `Shared/src` (`tests/suites/sharedBoundary.test.ts`).
- Logic-exporting barrel would drag screens into pure code (+ Portal / tests bundles).
- `@edge/*` files today: `whatsapp/rules.ts`, `whatsapp/sijilTemplates.ts`; guard test checks zero-import too.
- **Stays in SubsTrack:** screens, components, RN / expo-router hooks (`useTextField`, `useExportRows`, …), presentation helpers (`kindStyle`, `kindIcon`, `paymentMenu`, `reportColors`, `expenseCategoryIcon`), Supabase client + `storage.ts`, phone i18n (`core/i18n/setup.ts`, `languageStore`), offline layer (`core/offline/**`, `*.offline.ts`, `platform/offlineRepositories.ts`, `errorLog/`, `net/connectivity`).

### Offline-First (native only) — repository seam

Core rules in CLAUDE.md §5. Extras:
- Supabase class `Shared/src/modules/**/repository/XxxRepository.ts` (class only) + `OfflineXxxRepository` (SubsTrack `XxxRepository.offline.ts`); shared `implements IXxxRepository` → compiler keeps lockstep. Phone passes `createOfflineRepositories()`; Expo web gets `createSupabaseRepositories()` via the one temporary `Platform.OS` check in `configurePhone.ts`.
- Mirror = `expo-sqlite`. `runSyncIfDue()` serves both app-open triggers (cold start + session restore), measuring durable `sync_meta.last_sync_at`. Pull order meaningless b/c mirror has no FKs; push goes in `PUSH_WAVES` b/c server FKs are real; `withDbLock` b/c one connection → concurrent transactions interleave and fail.
- Online-only also covers every `CustomerRequest.*` (table not mirrored); `User.*` ones are edge fns.
- Requires `sql scripts/script.sql` (`updated_at` + BEFORE UPDATE triggers on every synced table) + **dev-client rebuild** (native module).

**Read `docs/offline.md` before touching any repository or the sync engine.**

### State Management — key rules

- Field names: `items` (not `customers.customers`), else semantic (`metrics`, `allowance`, `activeCustomers`, `monthGrid`, …).
- Selector: `useCustomerSlice((s) => s.items)`; `const slice = useCustomerSlice()` banned (re-renders on every change).
- `getStore()` in `Shared/src/state/globalStore.ts` (on `globalThis`, survives Metro Fast Refresh).
- **Global vs module store** (tests (a)/(b) in CLAUDE.md §5; (a) is the real coupling one store exists for). Module store = standalone `create()(immer(…))` under `Shared/src/modules/<module>/state/`, own `use…Store` hook, never in `GlobalState`. Global: `auth`, `billing` (`customers` reads allowance via `get().billing` to gate create; tenant-settings card + customers module render it), `tenantSettings`, `ledger`, `sales`, `products`, `customers`, `customerPlans`, `payments`, `branches`, `currencies`, `options`, `plans`, `users` (admin + ledger collector filter), `services` (admin + sales). `confirm` / `ui` = seams w/ no owning module (`confirm()` from every module's forms + `useUnsavedChangesGuard`; `ui` flipped by `PageHeader` on every screen, hosted once in `app/(app)/_layout.tsx`) → `Shared/src/shared/lib/confirmStore.ts`, `uiStore.ts`. The **seven** module stores: `dashboard`, `reports`, `collections` (ledger), `expenses`, `wallet`, `audit`, `signup` — each read by one module, no slice.
- ONE-WAY rule is why test (a) is right: once a slice needs a module store's data, it was never module-scoped. Cross reads via `getStore().getState()` (escape hatch, e.g. `Shared/src/shared/lib/confirm.ts`): `dashboard` + `reports` need `auth` + `tenantSettings`; `collections` needs `auth`, fans voids to `ledger` + `sales`.
- **Module store = slice minus `state.<key>.` prefix**: `create<XState>()(immer((set, get) => …))`, `set((s) => { s.items = … })` not `s.x.items`, `get().foo` own state, `getStore().getState().<slice>` peers. All else same (`items`, selector, `loading`/`error`, `reset()`, write-patch); components see no difference.
- **Registration**: `Shared/src/shared/lib/storeReset.ts` (`resetAllDomainStores`) + `Shared/src/state/refreshActiveData.ts` are plain explicit lists (one import + one line each). Leak = other org's audit trail, wallet cash, collections. **Global slices register in the first too** (`customerPlans`, `billing` were missing). **`options` must stay OUT**: `app_options` = global SaaS config fetched pre-auth to gate login screen UI; resetting it (or epoch-guarding its fetch) races bootstrap, silently hides that button (gotcha #156).
- **Session ends ONLY in** `Shared/src/shared/lib/session.ts` `endSession()`: bump data epoch, `auth.logout`, `resetAllDomainStores()`, clear `uiPrefStore`. Screens call only it; root layout keeps bare `resetAllDomainStores()` as safety net; Developer screen calls that alone (an import clears DATA, not device prefs) (gotcha #156).
- **Clearing stores doesn't stop an in-flight load** — it can write the old session's rows back and set `loaded`, blocking next user's fetch. Every arrival fetch captures `currentDataEpoch()` (`Shared/src/shared/lib/dataEpoch.ts`) before await, re-checks `isStaleEpoch()` before each `set`, in catch too. `resetAllDomainStores()` bumps the epoch → never separate. Orthogonal to `searchToken` ("still my search"), kept by the four stores that have one (gotcha #155).
- **Persist exceptions**: kept out of global store so domain state never persists. `uiPrefStore` persists via `runtime().storage` (AsyncStorage on phone, key `ui-pref-store`); `languageStore` to AsyncStorage directly. `uiPrefStore` names THIS org's rows → `endSession()` resets it, `reconcileBranchPref()` drops a branch the freshly loaded list can't explain; `languageStore` is device-owned, survives (gotcha #157).
- Caller-supplied params (currency, branch) include **the record a write acts on** when its old state matters: `customerSlice.deactivateCustomer / reactivateCustomer / deleteCustomer(customer)`, `bulkDeleteCustomers(customers)`, `customerPlanSlice.syncLines(customer, …)` — never looked up in `customers.items` (web never fills it; a miss once meant no allowance bump + a sync seeing NO saved lines, skipping the paid start-date lock). Exception: `customerSlice.createCustomer` + `customerPlanSlice.syncLines` read `limits` + `active` via `get().billing` (store's own numbers), then patch `billing.bumpActive` w/ a delta, never re-count. Slice template + cap example: `docs/features.md` → Allowances & Requests.
- **Web page stores** (`Web/src/state/`, CLAUDE.md §4): also `createPagedStoreWithMeta(fetchPage, filters, initialMeta)` when a page carries more than rows + total (Money received period total). Query holds page, page size, search, filters, header `branch` (`open(branch)`); plus `rows`, `total`. Register in `WEB_STORE_RESETS` (`webSession.ts`), not `storeReset.ts`. Writes go through the global slice so every other reader is patched. Add/delete `load()` again b/c a new row can land on any page, a removed one pulls the next up, total changes. Full rules: `docs/ui-patterns.md` → Freshness. A one-record list's factory store (`createSalesTable(customerId)`) lives in `useState`, read w/ zustand `useStore(store, selector)`, dropped on unmount → no `WEB_STORE_RESETS` entry, customers never share rows.
- **Write-patch extras**: a sale patches products `stockOnHand` (`applyStockDelta`, fed `stockDelta(before, after)` from cart lines) + unpaginated `monthlyTotals` behind month headers (`addMonthTotal`, `shared/lib/monthSections.ts`); `ledger.collect` fans the `Collection` to `sales.applyCollection`. Own-state lists (the two customer-scoped sales lists) use the same pure patches, `sales/utils/saleListPatch.ts`, so they can't drift. Month-bill / sale void re-read b/c they void every hand-over on the bill and one may have settled another on-screen bill the write never names; filtered/searched list b/c membership is a server question. Year arrows re-derive (gotcha #121). `owedVersion` exists b/c debts view is an aggregate incl. virtual months — how a pay-later sale reaches the debts panel below the sales panel that recorded it. Loop example: customer list's "collect all due". See gotchas #113 / #116 / #117.
- **`loaded` flag**: slices w/ `getX()` beside `fetchX()` (branches, currencies, customers, plans, products, users) set it on success, clear in `reset()`; `getX()` returns early when `loaded || loading`. Length check re-queried for **zero**-row tenants (fresh org hit DB on every form open) + let concurrent callers each fetch. `refreshActiveData` uses the flag so an empty-but-visited screen still refreshes.
- **eslint-disable ban**: slice actions are stable → list them in deps. Other compiler bail-outs (refs read during render, `try/finally`): gotcha #52.
